# DESIGN · 상태 스키마와 조작 규칙표 — 「현미경을 이용하여 세포의 크기 측정하기」

실험 id: `micrometer` · 관찰 대상: 자주달개비 잎 **공변세포** 영구표본

이 문서는 구현 전 설계다. 구현이 생기면 `docs/03-state-model.md` · `docs/04-interaction-rules.md`
자리로 옮겨 간다. 형식은 바나나랩의 두 문서를 그대로 따른다.

광학 수치(µm 환산, 배율별 눈금 간격, 허용 오차 각도 등)는 별도 담당이 정한다.
이 문서에서는 `[광학 설계 참조]` 로만 표시하고 **구조**만 다룬다.

---

## 0. 이 실험이 가르치려는 것 — 설계의 출발점

바나나랩은 **절차를 지켜야 볼 만한 것이 나온다**를 가르쳤다. 이 실험은 다르다.

> 접안마이크로미터 한 칸의 길이는 **기구의 성질이 아니라 배율의 함수다.**

접안마이크로미터는 접안렌즈 **안에** 있다. 그래서 대물렌즈를 바꿔도 화면에서 크기가 변하지 않는다.
대물마이크로미터와 표본은 재물대 **위에** 있다. 그래서 대물렌즈를 바꾸면 4배로 커진다.
이 비대칭이 이 실험의 전부다.

그래서 설계의 최우선 제약은 다음 한 줄이다.

> **접안마이크로미터 눈금은 배율이 바뀌어도 화면에서 한 치도 달라지지 않는다.**
> 렌더러가 이걸 어기고 함께 확대하는 순간, 이 실험이 가르치려는 것이 통째로 사라진다.

「배율을 바꾸면 눈금값을 다시 구해야 한다」를 **문장으로 알려 주는 순간에도** 같은 일이 벌어진다.
그래서 아래 규칙표에서 `SET_OBJECTIVE` 는 **눈금값에 대해 아무 말도 하지 않는다.** §6 에서 자세히 쓴다.

## 1. 상태 스키마

### 1.1 없어지는 것 — 바나나랩에서 지운다

| 지우는 것 | 왜 |
|---|---|
| `slides: {A, B, C}` 세 장 구조 | 대조군–아이오딘–수단 Ⅲ 비교가 없다. 이 실험에서 재물대에 오르는 것은 **대물마이크로미터**와 **표본** 둘뿐이고, 둘은 서로 대조군이 아니라 **차례로 쓰는 도구**다 |
| `sample { thickness, area }` | 학생이 시료를 만들지 않는다. **영구표본**이다 |
| `stain` · `drops` · `reactionT` | 시약이 없다. 색 변화가 없다. 시간이 흐를 이유가 없다 |
| `coverslip { placed, angleAtDrop, bubbles }` | 영구표본은 이미 봉입돼 있다. 덮개 유리를 덮는 조작이 없다 |
| `contaminated` | 스포이트가 없다 |
| `lensTouched` | 덮개 유리 없이 올릴 길이 없어졌다. 렌즈가 시료에 닿는 경로가 사라졌으므로 상태도 사라진다 |
| `tools.dropper` · `tools.forceps` · `tools.banana` | 위와 같은 이유 |
| `TICK` 액션과 `session` 의 시간 개념 | 반응이 없으므로 시간이 상태를 바꾸지 않는다. **되돌리기 기록이 밀려 나가던 문제도 함께 사라진다** |
| `quality.js` 의 `magnificationFactor` | 바나나랩은 "이 관찰은 400배에서 해야 한다" 였다. 이 실험은 **100배도 400배도 정답이다.** 배율이 감점 항목이면 안 된다 (§4.2) |

### 1.2 그대로 남는 것

| 남기는 것 | 이 실험에서의 뜻 |
|---|---|
| `microscope.objective` · `coarse` · `fine` · `diaphragm` · `lamp` | 그대로. 배율 집합은 `[광학 설계 참조]` — 다만 **최소 두 배율**과 **먼저 맞추는 저배율**이 있어야 구조가 성립한다 |
| `microscope.lowMagFocused` | 그대로. 저배율을 건너뛰면 초점 허용 범위가 좁아 사실상 못 찾는다 |
| `microscope.panX / panY` · `PAN_LIMIT` | **역할이 무거워진다.** 바나나랩에서는 "둘러보기" 였지만, 여기서는 절차 2단계 「중앙 정렬」 그 자체다 (§2.2) |
| `microscope.stage` | 그대로. 다만 값이 `'A'|'B'|'C'` 가 아니라 `'stageMic'|'specimen'` 이다 |
| `cracked` | 그대로. 고배율 조동나사는 여전히 유리를 깬다 (§5) |
| `seed` | 그대로. 세포 배치와 기구가 놓이는 각도의 흔들림을 재현 가능하게 만든다. **`Math.random()` 으로 바꾸지 말 것** |
| `session` 의 `level` · `mode` · `notes` · `captures` · `readStages` · `violations` · `tidy` · `log` · `history` · `undosLeft` | 그대로. 다만 `violations` / `tidy` 의 **항목이 달라진다** (§4.3) |

### 1.3 새로 필요한 것

```
eyepiece                          # 접안렌즈. 재물대 위가 아니라 렌즈 안이다 — 이 구분이 실험의 핵심이다
  micrometer   bool               # 접안마이크로미터가 끼워져 있는가
  flipped      bool               # 뒤집어 끼웠는가 (숫자가 좌우로 뒤집혀 보인다)
  angleDeg     0~360              # 접안렌즈를 돌린 각도. 연속값이다

items
  stageMic     { angleDeg, cracked, seed }   # 대물마이크로미터. 한 칸 = 10 µm [광학 설계 참조]
  specimen     { angleDeg, cracked, seed }   # 공변세포 영구표본
                                             # angleDeg 는 재물대에 놓일 때 정해진다 (난이도별 흔들림, §7)

picks          [ { kind, eyeDiv, stageDiv, gap, x, y } ]   # 학생이 시야에서 찍은 지점. 최대 2개
                                             # kind: 'scale' (눈금 겹친 곳) | 'cell' (세포의 끝)
                                             # gap: 찍은 자리에서 두 선이 어긋나 있던 정도 (칸, 0~0.5)

session
  calibrations [ { at, objective, eyeDivs, stageDivs, umPerDiv, gap, angleGap, focusErr } ]
  measurements [ { at, objective, target, cellDivs, calibrationAt, lengthUm } ]
```

**`microscope.stage` 가 「재물대에 무엇이 올라가 있는가」의 유일한 출처다.**
`items.*` 안에 `location` 을 또 두지 않는다. 두 곳에 적으면 어긋나는 순간
"재물대에는 표본이 있는데 표본은 상자 안에 있다" 같은 상태가 만들어진다.
바나나랩의 `PAN_LIMIT` 을 두 곳에 적지 않은 것과 같은 이유다.

#### 왜 `picks` 가 상태에 있는가

학생이 **세는 일을 앱이 대신하지 않는다.** 학생은 시야를 보고 겹친 지점 두 곳을 **직접 찍는다.**
앱이 하는 일은 찍힌 자리에서 접안 눈금 몇 번째 선과 대물 눈금 몇 번째 선이 가장 가까웠는지를
**읽어 주는 것**뿐이다. 뺄셈은 도구가 하고, 찾는 일은 눈이 한다.

여기서 `gap` 이 결정적이다. 학생이 **겹치지 않은 자리를 찍어도 막지 않는다.**
찍힌 자리의 어긋남이 `gap` 으로 그대로 남고, 그 오차가 눈금값에 그대로 들어가고,
같은 배율에서 두 번 구해 보면 **두 값이 서로 다르게 나온다.** 학생은 자기 손끝의 오차를
"틀렸습니다" 가 아니라 **자기가 적은 두 숫자의 차이**로 만난다.

#### 왜 `calibrations` 와 `measurements` 를 나누는가

`calibrations` 는 「접안 눈금 한 칸이 몇 µm 인가」, `measurements` 는 「이 세포가 몇 µm 인가」다.
둘을 한 테이블에 합치면 **어느 눈금값으로 어느 세포를 쟀는지**가 사라진다.
그 연결(`measurements[].calibrationAt`)이 이 실험의 핵심 함정을 드러내는 유일한 장치다 (§6).

그리고 **두 기록 모두 `objective` 를 함께 적는다.** 이것이 강제 없이 함정을 보이게 하는 방법이다.

## 2. 파생값 — 저장하지 않는다

바나나랩의 `coverage` / `excess` 자리다. **모두 연속값이다. 불리언이 아니다.**

| 함수 | 계산 | 무엇이 되는가 |
|---|---|---|
| `angleGap(state)` | 접안 눈금 각도와 재물대 위 물체 각도의 차. **180° 주기**로 접어 0~90° | 두 자가 얼마나 어긋났는가 |
| `alignment(state)` | `1 − min(angleGap / GAP_MAX, 1)` `[광학 설계 참조]` | 0~1. 나란한 정도 |
| `centerErr(m)` | `hypot(panX, panY) / PAN_LIMIT` | 0~1. 눈금자가 시야 중심에서 벗어난 정도 |
| `spanDivs(state)` | 시야 안에서 **두 눈금이 함께 보이는** 접안 칸 수. `centerErr` 가 크면 줄어든다 | 셀 수 있는 구간의 길이 |
| `focusErr(m)` | `\|coarse + fine\|` — 바나나랩 그대로 | 눈금선이 번진 정도 |
| `lineContrast(m)` | 조리개가 **어두워도 밝아도** 떨어진다 `[광학 설계 참조]` | §3 의 R-10 참조 |
| `readability(state)` | `focusFactor × lineContrast × (flipped ? k : 1)` `[광학 설계 참조]` | 0~1. **읽기 쉬움이지 정확함이 아니다** (§6.2) |
| `coincidences(state)` | 두 눈금선의 어긋남이 ε 이하인 지점들의 목록 `[{ eyeDiv, stageDiv, gap }]` | **이 실험의 `coverage` 에 해당하는 값** |
| `calibrationSpread(session, objective)` | 같은 배율에서 여러 번 구한 `umPerDiv` 의 흩어짐 | 학생이 자기 정밀도를 스스로 본다 |

### 2.1 `angleGap` — "맞았다/틀렸다" 로 두지 않는 이유

정렬을 불리언(`aligned: true/false`)으로 두면 화면이 할 수 있는 말이 "정렬하세요" 뿐이다.
연속값으로 두면 **시야가 각도를 그대로 그린다.**

| `angleGap` | 학생이 보게 되는 것 |
|---|---|
| 0° | 두 자가 완전히 나란하다. 일정 간격으로 선이 딱딱 맞아떨어진다 — 겹친 지점이 여러 곳 |
| 2~4° | 한쪽 끝에서는 맞고 반대쪽으로 갈수록 서서히 벌어진다. **겹친 지점이 시야 한쪽에만 있다** |
| 10° | 두 자가 한 곳에서만 스치듯 만난다. 겹친 지점 한 곳 — 두 지점이 없으니 칸 수를 잴 구간이 안 생긴다 |
| 30° 이상 | 두 자가 X 자로 교차한다. 눈금을 견줄 수 있는 자리가 없다 |

`coincidences` 의 **개수가 2 → 1 → 0 으로 줄어드는 것**이 곧 「눈금이 안 겹치면 칸 수를 셀 수 없다」다.
이건 규칙이 아니라 **그림의 귀결**이다. 어디에도 `if (!aligned) return blocked` 가 없다 (§6.1).

### 2.2 `centerErr` — 「중앙 정렬」을 체크박스로 만들지 않는 법

절차 2단계의 "중앙에 정렬한다" 를 확인 단계로 두면 누르기 게임이 된다. 대신 이렇게 한다.

눈금자가 시야 중심에서 밀려날수록 **시야 원 안에 남는 눈금 구간이 짧아진다**(`spanDivs` 감소).
구간이 짧으면 겹친 지점 두 곳 사이에 들어가는 칸 수가 적고, 칸 수가 적으면
같은 `gap` 오차가 눈금값에서 차지하는 비율이 커진다 — **눈금값이 거칠어진다.**

막히지 않는다. 그냥 **덜 정확해진다.** 그리고 그 거칢은 `calibrationSpread` 로 학생 눈에 보인다.

### 2.3 관찰 가능성 — 바나나랩의 `observability()` 자리

같은 뼈대를 쓴다. **합격선은 없고**, `worst`(가장 많이 깎은 항목)를 함께 돌려준다.

```
score = 100 × f정렬 × f초점 × f대비 × f구간
```

바나나랩에 있던 `f배율`·`f방울`·`f두께`·`f기포`·`f렌즈` 는 없다.
특히 **`f배율` 을 넣지 않는 것이 중요하다** — 이 실험에서 100배와 400배는 둘 다 옳다.
배율에 점수를 매기면 화면이 "400배로 올리세요" 라고 안내하게 되고,
그건 학생이 두 배율을 견주어 스스로 발견해야 할 것을 앱이 먼저 말해 버리는 것이다.

`flipped` 도 점수에서 뺀다. 이유는 §6.2.

## 3. 조작 규칙표

행은 두 종류다. **조작**은 학생이 직접 일으키는 액션, **자동 판정**은 다른 액션 안에서 도는 판정이다.
자동 판정 행을 새 액션으로 분리하지 말 것.

| ID | 종류 | 조작 · 판정 | 어디서 도는가 | 순진한 설계 (강제) | 이 프로젝트 (귀결) |
|---|---|---|---|---|---|
| M-01 | 조작 | 접안마이크로미터를 접안렌즈에 끼운다 | `INSERT_OCULAR {flipped}` | 방향 확인 후에만 허용 | 진행된다. 뒤집어 끼우면 **시야의 숫자가 좌우로 뒤집혀 보인다.** 칸 간격은 그대로다 |
| M-02 | 조작 | 접안마이크로미터를 빼낸다 | `REMOVE_OCULAR` | — | 진행된다. 시야에서 눈금이 사라진다. 뒤집힌 것을 고치는 길이기도 하다 |
| M-03 | 조작 | 접안마이크로미터를 안 끼운 채 관찰 | `PLACE_ON_STAGE` · `SET_OBJECTIVE` 등 전부 | "먼저 접안마이크로미터를 끼우세요" | 진행된다. **시야에 견줄 눈금이 없다.** 찍어도 칸으로 옮길 값이 없어 기록이 빈 채로 남는다 |
| M-04 | 조작 | 접안렌즈를 돌린다 | `ROTATE_EYEPIECE {deltaDeg}` | 정해진 각도로만 | 진행된다. 연속값이다. `angleGap` 이 바뀌고 시야에서 두 자가 벌어지거나 나란해진다 |
| M-05 | 조작 | 재물대에 올린다 (눈금자 / 표본) | `PLACE_ON_STAGE {item}` | 순서 강제 | 진행된다. **표본을 먼저 올려도 막지 않는다.** 견줄 눈금자가 없으니 칸 수만 세어질 뿐이다 |
| M-06 | 조작 | 이미 올라간 것이 있는데 또 올린다 | `PLACE_ON_STAGE` | 차단 | **바꿔 올린다.** 클립에는 한 장만 들어가므로 앞엣것은 내려온다. 무엇이 내려가고 무엇이 올라갔는지 말한다 |
| M-07 | 조작 | 재물대에서 내린다 | `REMOVE_FROM_STAGE` | — | 진행된다. 대가 없는 되돌아가기 길 |
| M-08 | 조작 | 재물대를 옮긴다 (중앙 정렬) | `MOVE_STAGE {dx, dy}` | "중앙 정렬 확인" 체크 | 진행된다. `±PAN_LIMIT` 에서 더 안 갈 뿐 막지 않는다. §2.2 대로 **눈금값이 거칠어진다** |
| M-09 | 조작 | 대물렌즈를 바꾼다 | `SET_OBJECTIVE {objective}` | 눈금값 재측정 강제 · 경고 | 진행된다. **눈금값에 대해 아무 말도 하지 않는다.** 재물대 위 눈금 간격만 4배로 벌어지고 접안 눈금은 그대로다 (§6.3) |
| M-10 | 조작 | 저배율을 건너뛰고 고배율 | `SET_OBJECTIVE` | 차단 | 진행된다. 초점 허용 범위가 좁아 **사실상 눈금선을 못 찾는다** (바나나랩 R-11 그대로) |
| M-11 | 조작 | 고배율에서 조동나사 | `COARSE_FOCUS {delta}` | 차단 | **유리에 금이 간다.** 조작 자체는 막지 않는다 — 돌아가고, 깨진다 (§5) |
| M-12 | 조작 | 미동나사를 돌린다 | `FINE_FOCUS {delta}` | — | 언제나 안전하다. 눈금선의 번짐이 줄어든다. 저배율에서 맞으면 `lowMagFocused` 가 선다 |
| M-13 | 조작 | 조리개를 조작한다 | `SET_DIAPHRAGM {value}` | 경고 | 진행된다. **양쪽 다 나빠진다** — 어두우면 눈금선이 배경에 묻히고, 너무 밝으면 가는 선이 하얗게 날아간다 |
| M-14 | 조작 | 겹친 지점을 찍는다 | `PICK_SCALE {x, y}` | 겹친 곳에만 찍히게 스냅 | **아무 데나 찍힌다.** 가장 가까운 두 선을 잡고, 그 자리의 어긋남을 `gap` 으로 남긴다 |
| M-15 | 조작 | 찍은 지점을 지운다 | `CLEAR_PICKS` | — | 언제나 된다. **되돌리기를 쓰지 않는다** (§7.1) |
| M-16 | 조작 | 눈금 한 칸의 길이를 기록한다 | `RECORD_CALIBRATION` | 정렬·초점 검사 후에만 | **언제나 기록된다.** 잘 안 맞은 채 구한 값도 기록되고, 그 값에 `objective`·`gap`·`angleGap` 이 함께 붙는다 |
| M-17 | 조작 | 두 지점 사이에 대물 눈금이 한 칸도 없다 | `RECORD_CALIBRATION` | 차단 | 기록된다. 한 칸의 길이를 구할 수 없으므로 `umPerDiv` 가 **빈칸으로 남는다.** 그 기록을 쓰면 세포 크기도 빈칸이다 |
| M-18 | 조작 | 세포의 양 끝을 찍는다 | `PICK_CELL {x, y}` | 세포 경계에 스냅 | 아무 데나 찍힌다. **세포가 아닌 것을 재도 막지 않는다.** 기록에 「잰 대상」이 남는다 |
| M-19 | 조작 | 세포 크기를 기록한다 | `RECORD_MEASUREMENT {calibrationAt}` | 현재 배율 눈금값만 선택 가능 | **어느 눈금값이든 고를 수 있다.** 고른 것의 배율과 지금 배율을 **둘 다 사실로 적는다** (§6.3) |
| M-20 | 조작 | 눈금값이 하나도 없는데 세포를 기록 | `RECORD_MEASUREMENT` | 차단 | 기록된다. **칸 수만 남는다.** 나중에 눈금값을 구해 붙일 수 있다 |
| M-21 | 조작 | 기록을 지운다 | `DELETE_CALIBRATION` · `DELETE_MEASUREMENT {at}` | — | 언제나 된다. 관찰을 무르는 것이 아니라 **무엇을 근거로 삼을지 고르는 일**이다 |
| M-22 | 조작 | 흐린 상을 결과로 기록 | `CAPTURE` | 차단 | 허용한다. 정리 단계에 "왜 흐렸을까?" 문항이 붙는다 (바나나랩 R-15 그대로) |
| M-23 | 조작 | 새 기구를 꺼낸다 | `NEW_ITEM {kind}` | — | 금이 간 기구를 버리고 비품장/표본상자에서 새것을 꺼낸다. **막다른 길을 막는 유일한 장치다** (§5) |
| M-24 | 조작 | 정리한다 | `PUT_AWAY {kind}` | — | 접안마이크로미터를 케이스에, 표본을 상자에, 대물렌즈를 최저배율로, 조명 끄기. 늦게 해도 위반 기록에서 지워진다 |
| M-25 | 자동 판정 | 겹친 지점 찾기 | 렌더 때마다 `coincidences(state)` | 별도 「정렬 확인」 단계 | 판정하지 않는다. **강조 표시도 하지 않는다.** 그림만 그리고 찾는 일은 학생 눈이 한다 (§6.1) |
| M-26 | 자동 판정 | 찍은 자리의 어긋남 | `PICK_SCALE` 안의 `gap` | 스냅 또는 경고 후 차단 | `loose-pick` 태그. **얼마나 어긋났는지를 사실로 말하고 그대로 잡는다.** 오차는 눈금값에 그대로 들어간다 |
| M-27 | 자동 판정 | 눈금값의 배율 대조 | `RECORD_MEASUREMENT` 안 | "배율이 다릅니다! 다시 측정하세요" | `calib-other-mag` 태그. **두 배율을 사실로 나란히 말할 뿐, 틀렸다고 하지 않는다** (§6.3) |
| M-28 | 자동 판정 | 파손 | `COARSE_FOCUS` 안의 `objective === 고배율 && stage` | 차단 | `cracked` 가 서고 재물대에서 내려온다. **일어난 일**이지 막은 것이 아니다 |
| M-29 | 자동 판정 | 금 간 기구를 다시 올린다 | `PLACE_ON_STAGE` 안의 `cracked` | — | **`blocked(BROKEN)`. 이 실험의 유일한 하드 게이트다** (§5) |
| M-30 | 자동 판정 | 마칠 때 정리 점검 | `CHECK_TIDY` (보고서를 열 때 한 번) | 정리해야 보고서 열림 | 막지 않는다. 안 한 것이 `violations` 에 적힐 뿐이다. **감점하지 않는다** |

그대로 가져오는 것 (표에서 뺌): `SAVE_NOTE` · `MARK_READ` · `UNDO` · `NOTE_VIOLATION`.
바나나랩과 동작이 같다.

### 4.2 배율에 대해 하지 않는 말

`SET_OBJECTIVE` 는 다음 문장을 **절대 내지 않는다.**

- ❌ 「배율을 바꿨습니다. 눈금 한 칸의 길이를 다시 구하세요.」
- ❌ 「이전 눈금값은 100배 기준입니다. 지금 배율과 다릅니다.」
- ❌ 기존 `calibrations` 에 「만료」·「무효」 표시를 붙이는 것

이 문장 하나가 이 실험의 학습 목표 전부를 대신 말해 버린다.
그 대신 §6.3 의 세 갈래로 학생이 **스스로** 도달하게 한다.

### 4.3 안전·정리 항목 — 시야로 말할 수 없는 것

시약이 없으므로 바나나랩의 `hands-unwashed` · `cap-left-open` · `waste-left` 는 사라진다.
대신 이 실험의 항목이 들어온다. 전부 **결과에 영향을 주지 않으므로** 시야로 말할 수 없고,
`session.violations` 에 기록해 자기 평가의 '가치·태도' 에 보여만 준다. **감점하지 않는다.**

## 5. 하드 게이트 — 딱 하나, 그리고 왜 그 하나뿐인가

`AGENTS.md` §2.1 이 허용하는 것은 둘뿐이다.

### `IMPOSSIBLE` — **이 실험에는 자리가 없다**

바나나랩의 예(닫힌 뚜껑 안으로 물체 넣기)에 해당하는 자리를 찾아보았고, 전부 다른 답이 낫다.

| 후보 | 왜 하드 게이트가 아닌가 |
|---|---|
| 접안마이크로미터가 이미 있는데 또 끼운다 | 빼고 끼우면 된다. **교체**로 처리 |
| 재물대에 두 장을 동시에 올린다 | 클립에 한 장만 들어가니 앞엣것이 내려올 뿐이다. **교체**로 처리 (M-06) |
| 접안마이크로미터를 재물대에 올린다 | **물리적으로 가능하다.** 올려 봐야 시야에 눈금이 안 보이고 유리 조각만 보인다. 허용하고 그대로 보여 준다 |
| 접안마이크로미터 없이 접안렌즈를 돌린다 | 돌아간다. 아무 일도 안 일어난다. 말 없이 `ok` |

억지로 만들지 않았다. **없다.**

### `BROKEN` — 하나 있다 (M-29)

고배율에서 조동나사를 돌리면 대물렌즈가 재물대 위 유리를 누른다. 교과서가 경고하는 바로 그 일이다.

- **조작 자체는 막지 않는다.** `COARSE_FOCUS` 는 돌아가고, `cracked` 가 서고,
  기구가 재물대에서 내려온다. 결과는 `happened` 다 (M-28).
- 막히는 것은 **그다음**이다. 금 간 유리를 다시 올리려 하면 `blocked(BROKEN)` —
  이미 벌어진 파손 때문에 그 물건을 더 쓸 수 없는 것이지, 조작을 금지한 것이 아니다.
  바나나랩의 `MOUNT` 가 금 간 슬라이드를 막는 구조와 완전히 같다.

**그리고 반드시 `NEW_ITEM` 을 함께 만든다 (M-23).**
대물마이크로미터는 이 실험에서 유일한 기준자다. 그것이 깨지고 새것을 꺼낼 길이 없으면
실험이 거기서 끝난다 — 그건 결과가 아니라 **막다른 길**이다.
바나나랩이 `NEW_SLIDE` 를 뒤늦게 넣은 것과 같은 이유이므로, 처음부터 넣는다.
새것을 꺼내면 정렬과 초점이 초기화된다. 그 다시-맞추기가 이미 충분한 대가다.

## 6. 세 가지 함정을 결과로 보이는 법

### 6.1 눈금이 안 겹치면 칸 수를 셀 수 없다

**규칙을 만들지 않는다.** 어디에도 `if (angleGap > x) return blocked` 가 없다.

1. 시야는 두 눈금자를 **각자의 각도 그대로** 그린다. 어긋난 만큼 벌어져 보인다.
2. **겹친 지점을 강조 표시하지 않는다.** 형광펜을 칠하면 앱이 학생 대신 본 것이 된다.
   `coincidences()` 는 렌더러가 선을 어떻게 그릴지 정할 때만 쓰고, 화면에 표시하지 않는다.
3. 학생은 언제나 찍을 수 있다. 안 겹친 자리를 찍으면 `gap` 이 크게 남는다 (M-26).
4. 그 오차가 `umPerDiv` 에 그대로 들어간다.
5. **같은 배율에서 두 번 구해 보면 두 값이 다르다** (`calibrationSpread`).

탐구 노트가 이렇게 묻는다 — 「같은 배율에서 두 번 구해 나란히 적으세요. 값이 같습니까?」
정답을 채점하는 문항이 아니다. **자기가 적은 두 숫자를 나란히 놓게 하는 문항**이다.

찍기를 무르는 데 되돌리기를 쓰게 하면 안 된다. `CLEAR_PICKS` 가 무료로 있다 (M-15, §7.1).

### 6.2 뒤집어 끼우면 숫자가 거꾸로 보인다

먼저 사실을 정확히 하자. **뒤집어 끼워도 측정값은 틀리지 않는다.**
칸 간격은 그대로이고, 「몇 칸인가」는 방향과 무관하다. 이건 정확도 함정이 아니라 **읽기 함정**이다.

그래서 이렇게 설계한다.

- 시야에서 **숫자만 좌우로 뒤집혀** 보인다. 눈금선 간격은 한 치도 안 변한다.
- 대물마이크로미터의 숫자는 왼→오른쪽으로 늘고, 뒤집힌 접안 눈금은 오른→왼쪽으로 는다.
  **두 자의 숫자가 서로 반대로 흐른다.** 「접안 3번에서 8번까지」를 읽으려는 순간 학생이 걸려 넘어진다.
- `readability` 를 깎지만 **`observability` 점수에서는 뺀다.**
  점수를 깎으면 앱이 "이건 틀린 상태다" 라고 말하는 셈인데, 사실이 아니다.
  숫자가 뒤집혀 보이는 것 자체가 이미 충분한 신호다.
- 고치는 길은 대가가 없다: 빼서(M-02) 다시 끼우면(M-01) 된다.

이 함정이 가르치는 것은 「틀린 값을 얻는다」가 아니라 **「기구를 읽을 줄 알아야 한다」**다.
그래서 결과가 아니라 읽기에만 영향을 준다.

### 6.3 배율을 바꾸고 눈금값을 다시 안 구하면 4배 틀린다 ★

**이 실험이 가르치려는 핵심이다. 그래서 절대 문장으로 알려 주지 않는다.**
대신 학생이 도달할 수 있는 길을 **세 갈래로** 열어 둔다. 하나만 걸려도 도달한다.

#### 갈래 ㄱ — 시야가 말한다 (가장 강한 길)

배율을 올리면 재물대 위의 대물마이크로미터 눈금 간격이 화면에서 **4배로 벌어진다.**
접안마이크로미터 눈금은 접안렌즈 안에 있으므로 **한 치도 안 변한다.**

이 대비가 그림 하나로 「접안 한 칸에 대물 몇 칸이 들어가는가」가 배율마다 다르다는 것을 말한다.
100배에서 접안 40칸 = 대물 5칸이던 것이, 400배에서는 접안 40칸 = 대물 1.25칸으로 보인다.
**학생이 대물마이크로미터를 다시 올려 보기만 하면 눈으로 보인다.**

> 그래서 §0 의 제약이 렌더러 계약이 된다. `SET_OBJECTIVE` 는 재물대 위 물체의 축척만 바꾸고,
> **접안 눈금 레이어는 건드리지 않는다.** 실수로 함께 확대하면 이 실험은 아무것도 안 가르친다.
> 이건 테스트로 못 박아야 한다 — 「배율을 바꿔도 접안 눈금의 화면상 간격이 같다」.

#### 갈래 ㄴ — 기록에 배율 도장이 찍힌다

`calibrations[]` 의 모든 행에 `objective` 가 붙는다. 눈금값 카드는 언제나
「**100배에서 구함** · 한 칸 = 2.5 µm」처럼 배율과 함께 보인다 `[광학 설계 참조]`.

`RECORD_MEASUREMENT` 에서 학생이 **어느 눈금값을 쓸지 직접 고른다.** 이것이 결정 지점이다.
다른 배율의 것을 골라도 막지 않는다. 대신 M-27 이 사실을 말한다.

> 「이 눈금값은 **100배**에서 구한 것이고, 방금 센 칸 수는 **400배**에서 센 것입니다.」

이 문장은 **틀렸다고 말하지 않는다.** 무엇이 잘못됐는지도, 어떻게 하라고도 말하지 않는다.
두 개의 사실을 나란히 놓을 뿐이다. 그리고 실제로 학생이 일부러 그 값을 쓰고 싶을 수도 있다 —
값을 쓰는 것도 허용된다. `happened` 이지 `blocked` 가 아니다.

#### 갈래 ㄷ — 자기가 적은 두 숫자가 나란히 놓인다 (마지막 그물)

같은 공변세포를 100배와 400배에서 잰다. 절차의 마지막 단계가 이것이다.

- 배율마다 눈금값을 제대로 다시 구했다면 → **두 배율에서 같은 µm 가 나온다.**
  칸 수는 4배로 늘었지만 한 칸의 길이가 1/4이 됐기 때문이다.
- 100배 눈금값을 400배 측정에 그대로 썼다면 → **한쪽이 다른 쪽의 4배로 나온다.**

앱은 "정답입니다" 라고 말하지 않는다. 탐구 노트 정리 문항이 이렇게 묻는다.

> 「같은 공변세포를 100배와 400배에서 잰 값을 나란히 적으세요. 두 값이 같습니까?
>  다르다면, 어디서 갈렸을까요?」

**두 값이 일치하는 것이 곧 성공 신호다.** 이 실험은 스스로를 검산하는 구조를 이미 갖고 있다.
앱이 채점할 이유가 없다. 나란히 놓아 주기만 하면 된다.

그래서 기록 화면은 `measurements` 를 **배율별로 묶어 나란히** 쌓는다. 실험 도중에도 보인다.

## 7. 되돌리기와 난이도

### 7.1 되돌리기

바나나랩의 세 분류를 그대로 쓰되, 액션이 바뀐 만큼 배치가 달라진다.

| 분류 | 이 실험의 액션 | 왜 |
|---|---|---|
| 쌓지 않음 (`TRANSIENT_ACTIONS`) | `MOVE_STAGE` · `NOTE_VIOLATION` · `CHECK_TIDY` · `MARK_READ` | 시야를 둘러보는 것은 조작이 아니다. **`TICK` 은 아예 없어졌다** — 반응이 없으므로 시간이 상태를 바꾸지 않고, 바나나랩에서 되돌리기 기록이 밀려 나가던 문제도 함께 사라진다 |
| 하나로 합침 (`CONTINUOUS_ACTIONS`) | `ROTATE_EYEPIECE` · `FINE_FOCUS` · `COARSE_FOCUS` · `SET_DIAPHRAGM` · `SAVE_NOTE` | 슬라이더를 한 번 끄는 동안 수십 번 디스패치된다. 되돌리기는 **끌기 전**으로 돌아가야 한다. `ROTATE_EYEPIECE` 가 여기 새로 들어온다 |
| 그대로 쌓음 | 나머지 전부 | |

**되돌리기가 쓰이면 안 되는 자리에는 무료 액션을 따로 둔다.** 이게 바나나랩에서 배운 것이다.

| 이런 일에는 | 되돌리기 대신 |
|---|---|
| 잘못 찍은 지점 | `CLEAR_PICKS` (M-15) |
| 남기고 싶지 않은 눈금값·측정값 | `DELETE_CALIBRATION` · `DELETE_MEASUREMENT` (M-21) |
| 잘못 올린 기구 | `REMOVE_FROM_STAGE` (M-07) |
| 뒤집어 끼운 접안마이크로미터 | `REMOVE_OCULAR` → `INSERT_OCULAR` (M-02 → M-01) |
| 잘못 바꾼 배율 | `SET_OBJECTIVE` 를 다시 (M-09) |

되돌리기가 1회뿐인 3단계에서, 그 한 번이 **오타를 지우는 데** 쓰이면 기능이 사실상 없는 것이다.
찍기는 이 실험에서 가장 자주 다시 하는 조작이므로 반드시 무료여야 한다.

`DELETE_*` 는 바나나랩 `DELETE_CAPTURE` 의 `at` 규약을 그대로 지킨다 —
**배열 인덱스가 아니라 한 번 붙으면 안 바뀌는 번호로 지운다.**
`measurements[].calibrationAt` 이 그 번호를 가리키고 있어서, 인덱스로 지우면
남의 눈금값을 가리키게 된다. 그리고 지워진 눈금값을 참조하던 측정값은
**지우지 않고 `calibrationAt` 만 끊는다** — 학생이 센 칸 수는 여전히 자기가 관찰한 사실이다.

### 7.2 난이도 3단계

바나나랩의 원칙을 그대로 가져온다. **난이도는 결과를 바꾸지 않는다. 앱이 말해 주는 양을 바꾼다.**
같은 조작이 1단계에서는 틀리고 3단계에서는 맞는 일 같은 건 없다.

| | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| 되돌리기 | 무제한 | 3회 | 1회 |
| 기구가 재물대에 놓이는 각도 | 항상 0° — 정렬은 접안렌즈만 돌리면 된다 | seed 로 정해지는 작은 흔들림 | 더 큰 흔들림 `[광학 설계 참조]` |
| 뒤집어 끼웠을 때 | 시야도 뒤집히고, **토스트도 사실을 말한다** | 토스트가 짧아진다 | **말하지 않는다. 시야만 말한다** |
| 찍은 자리의 `gap` | 칸 단위로 알려 준다 (「0.3칸 어긋났습니다」) | 「조금 어긋났습니다」 | **말하지 않는다. 기록에만 남는다** |
| `RECORD_MEASUREMENT` 의 눈금값 선택 | 지금 배율에서 구한 것이 기본 선택 | 기본 선택 없음 | 기본 선택 없고, M-27 의 배율 대조 문구도 **줄어든다** |
| 조리개·초점 초깃값 | 눈금선이 잘 보이는 값에서 시작 | 조금 어긋난 값 | 크게 어긋난 값 |
| 관찰 가능성 점수의 `worst` 안내 | 항목 이름을 보여 준다 | 보여 준다 | 점수만 보여 준다 |

1단계에서 눈금값을 기본 선택해 주는 것이 §6.3 의 함정을 없애지 않는가?
없애지 않는다. **1단계는 처음 해 보는 학생이 절차를 한 번 끝까지 밟아 보는 단계**이고,
그때에도 갈래 ㄱ(시야)과 갈래 ㄷ(두 값 나란히 놓기)은 그대로 살아 있다.
2·3단계에서 선택이 학생에게 넘어가면서 갈래 ㄴ이 열린다.
