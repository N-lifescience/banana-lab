# 04 · 조작 규칙 — 강제에서 귀결로

**이 문서가 프로젝트의 핵심이다.**

## 원칙

초기 설계에서는 전제조건을 만족하지 못하면 진행을 막았다. 그러나 학생은 절차대로만 하지 않는다.
막아 버리면 배우는 것은 "정해진 대로 눌러야 넘어간다"뿐이고, 실험하는 느낌도 사라진다.

> **거의 모든 조작을 허용하고, 대신 결과로 답한다.**

## 결과 종류는 셋뿐

| outcome | 뜻 |
|---|---|
| `ok` | 뜻대로 됐다. 할 말이 있으면 **초록**으로 무엇이 바뀌었는지 알린다 (없어도 된다) |
| `happened` | 진행됐다. 다만 이런 일이 일어났다 — **대부분 여기 해당** |
| `blocked` | 진행되지 않았다 — **아래 두 사유에만 허용** |

`ok` 를 「별말 없음」으로 읽지 말 것. **화면에 띄울지는 `outcome` 이 아니라 메시지가 있는가로
정한다**(`createStore`). 앞서 `outcome !== 'ok'` 로 걸렀더니, 잘된 조작이 무엇을 바꿨는지
말해 주는 문장 열넷이 화면에 한 번도 뜨지 않았다.

## 하드 게이트가 허용되는 단 두 가지

```js
BLOCKING_REASONS = {
  IMPOSSIBLE: 'impossible',  // 물리적으로 성립하지 않음 (닫힌 뚜껑 안으로 물체 넣기)
  BROKEN:     'broken',      // 기구가 파손돼 재제작이 필요함
}
```

이 외의 사유로 `blocked` 를 돌려주면 `rules.js` 의 `blocked()` 헬퍼가 **던진다**.
그리고 `tests/rules.test.js` 의 「하드 게이트는 두 종류뿐이다」가 모든 액션을 훑어 다시 검사한다.

새 하드 게이트가 필요하다고 판단되면 **코드를 고치지 말고 사람에게 물어본다.**

## 방울 수 — 연속 반응 곡선

"두 방울"은 지시이지 조건이 아니다.

```js
coverage = min(drops / 2, 1)          // 용액이 시야에 도달한 범위
excess   = clamp((drops − 2) / 3, 0, 1) // 넘친 정도
```

| 방울 | coverage | excess | 학생이 보게 되는 것 |
|---|---|---|---|
| 0 | 0.00 | 0.00 | 염색 없음. (가) 대조군과 구별되지 않는다 |
| 1 | 0.50 | 0.00 | 용액이 떨어진 자리 주변만 물든다. **시야 안에 경계가 보인다** |
| 2 | 1.00 | 0.00 | 시야 전체가 고르게 염색. 대비가 가장 좋다 |
| 3 | 1.00 | 0.33 | 배경 세포질까지 옅게 물든다 |
| 4 | 1.00 | 0.67 | 배경이 진하게 착색. 구분이 어려워진다 |
| 5–6 | 1.00 | 1.00 | 액이 넘쳐 덮개 유리가 뜬다. 상이 둘로 겹친다 |

염색 강도는 보간하지 않고 **없음 / 옅음(전이 구간) / 완전** 세 단계로 양자화한다.
플랫 팔레트를 닫아 두기 위해서다. 05번 문서 참조.

## 규칙표

행은 두 종류다. **조작**은 학생이 직접 일으키는 액션이고,
**자동 판정**은 독립 액션이 아니라 다른 액션 안에서 도는 판정이다.
자동 판정 행을 새 액션으로 분리하지 말 것 — 판정이 일어나는 액션은 「어디서 도는가」 열에 적혀 있다.

| ID | 종류 | 조작 · 판정 | 어디서 도는가 | 순진한 설계 (강제) | 이 프로젝트 (귀결) |
|---|---|---|---|---|---|
| R-01 | 조작 | 바나나 껍질을 벗긴다 | `PEEL_BANANA` | — | 진행된다. 벗기지 않은 채 문지르면 과육이 묻지 않는다 |
| R-02 | 조작 | 시료를 두껍게 문지름 | `SMEAR` | 진행 차단 | 진행된다. 시야에 어두운 층이 덮여 구조가 뭉개진다 |
| R-03 | 자동 판정 | 두께 검사 | `SMEAR` 안의 `thickness > 0.6` | 별도 확인 단계 | `too-thick` 태그가 붙고 `isTooThick()` 이 시야로 넘긴다 |
| R-04 | 조작 | 스포이트에 용액을 채운다 | `FILL_DROPPER` | — | 진행된다. 남은 용액이 있으면 R-06 이 함께 돈다 |
| R-05 | 조작 | 방울 수가 2가 아님 | `DROP` | 진행 차단 | 진행된다. 위 곡선대로 시야가 달라진다 |
| R-06 | 자동 판정 | 교차 오염 | `FILL_DROPPER` · `DROP` 안의 `rinsed` | 경고 후 차단 | `cross-contamination` 태그. **한 시야에 청람색과 선홍색이 함께** 나타난다 |
| R-07 | 자동 판정 | 색 변화 완료 | `TICK` 이 `reactionT` 를 올리고 `PLACE_COVERSLIP` 이 읽는다 | 반응 전 덮개 차단 | 덜 됐으면 `early-cover` 태그. 반응은 덮개 유리 아래에서 계속된다 |
| R-08 | 조작 | 덮개 유리를 수직으로 떨어뜨림 | `PLACE_COVERSLIP` | 경고 | 진행된다. 기포가 생겨 시야를 가린다 |
| R-09 | 자동 판정 | 기포 검사 | `PLACE_COVERSLIP` 안의 `bubblesFromAngle(angleDeg)` | 별도 확인 단계 | 각도로 개수가 정해지고 `bubbles` 태그가 붙는다 |
| R-10 | 조작 | 덮개 유리 없이 재물대에 올림 | `MOUNT` | 차단 | 진행된다. 400배로 올리면 렌즈가 시료에 닿는다 |
| R-11 | 조작 | 저배율을 건너뛰고 400배 | `SET_OBJECTIVE` | 차단 | 진행된다. **초점 허용 범위가 1/10** 이라 사실상 못 찾는다 |
| R-12 | 조작 | 고배율에서 조동나사 | `COARSE_FOCUS` | 차단 | **슬라이드에 금이 간다.** 허용된 하드 귀결 |
| R-13 | 조작 | 미동나사를 돌린다 | `FINE_FOCUS` | — | 언제나 안전하다. 저배율에서 맞으면 `lowMagFocused` 가 선다 |
| R-14 | 조작 | 조리개를 닫은 채 400배 | `SET_DIAPHRAGM` | 경고 | 진행된다. 어두워서 경계가 안 보인다 |
| R-15 | 조작 | 흐린 상을 결과로 기록 | `CAPTURE` | 차단 | 허용한다. 정리 단계에 "왜 흐렸을까?" 문항이 붙는다 |

기포 함수:

```js
bubbles = round(6 × clamp((|angleDeg − 45| − 10) / 45, 0, 1))
// 35°~55° → 0개, 수직(90°)이나 눕힘(0°)에 가까울수록 최대 6개
```

## 관찰 가능성 — 합격이 아니라 상태

진행을 막지 않는 대신, 지금 시야가 얼마나 볼 만한지를 0~100 연속값으로 계산해 결과와 함께 저장한다.
**합격선은 없다.** 학생은 자기 값이 왜 그 값인지 설명하게 된다.

```
score = 100 × f방울 × f초점 × f광량 × f두께 × f기포 × f배율 × f렌즈
```

`observability()` 는 `worst` — 가장 많이 깎은 항목 — 도 함께 돌려준다.
UI는 이걸로 "무엇부터 고칠지"를 안내한다.

## 안전 규칙만은 예외

시약병 마개 방치, 용액 묻은 손으로 기구 조작, 폐액 미처리는 결과에 영향을 주지 않으므로
시야로 말할 수 없다. `session.violations` 에 기록해 자기 평가의 '가치·태도' 항목에 보여 준다.
**감점하지 않는다 — 본인이 보게 한다.**
