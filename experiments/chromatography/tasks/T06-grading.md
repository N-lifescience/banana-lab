# T06 · 서술형 첨삭 — 소재 목록

## 비용은 비대칭이다

**맞는 답을 부족하다고 하는 쪽이 훨씬 비싸다.** 아무것도 점수 매기지 않고 막지도 않으므로,
느슨해서 생기는 손해는 거의 없고 빡빡해서 생기는 손해는 **학생이 글쓰기를 그만두는 것**이다.

- **소재(subject)** 로 본다 — 「색소」·「전개율」처럼 있어야 할 것이 들어 있는가
- 길이는 문장 수가 아니라 **공백 뺀 글자 수**로 잰다
- 「왜냐하면」 같은 깊이 단어는 **힌트일 뿐** 판정 근거로 쓰지 않는다
- 결과는 `pass` / `more` / `unavailable` 셋. **틀렸다는 판정은 없다**

## 이 실험의 소재 목록

| 문항 | 있어야 할 소재 |
|---|---|
| 왜 색소가 갈라지는가 | 용해도 / 흡착 / 이동 속도 — **하나만 들어 있어도 통과** |
| 띠 순서를 설명하라 | 색소 이름 둘 이상 + 위·아래 관계 |
| 왜 원점이 잠기면 안 되나 | 색소 / 씻김·녹음 |
| 흐리게 나온 까닭 | 찍은 횟수 / 색소량 / 시료 — 하나 |

**동의어를 넉넉히 받는다.** 「전개율」·「Rf」·「알에프」는 같은 것이다.
「청록」과 「청녹」은 표기만 다르므로 **채점에서는 둘 다 받고**, 화면 문자열에서는 「청록」만 쓴다.

## 채점 테스트는 반드시 **바깥에서 만든 문장**으로

구현한 사람이 자기 키워드 목록을 보고 만든 테스트는 아무것도 검증하지 못한다.
바나나랩에서 실제로 겪었다 — 전체 99개가 통과하는 상태에서, 바깥에서 새로 쓴 학생 문장
9개 중 **6개가 거짓 부정**이었다.

→ 채점 로직을 **안 본 세션**(서브에이전트)에게 학생 답안을 쓰게 해서 홀드아웃 테스트를 만든다.
`tests/grading.holdout.test.js` 가 그 자리다.

## 합격 기준

- [ ] 홀드아웃 문장 중 **거짓 부정 0건**
- [ ] 빈칸에는 첨삭이 뜨지 않는다
- [ ] 「틀렸다」는 판정이 없다 (테스트)

## 검증 명령

```bash
node scripts/check-grading.mjs
npm run check
```
