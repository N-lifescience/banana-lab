# 07 · 모둠 결과 보드와 배포

## 세 서비스는 경쟁 관계가 아니다

Vercel과 Netlify는 **호스팅**, Supabase는 **백엔드**다. 하나를 고르는 게 아니라
*호스팅 하나 + 백엔드 하나*를 조합한다.

| 서비스 | 역할 | 이 프로젝트에서 |
|---|---|---|
| Vercel | 정적 호스팅 + 엣지 함수 | 시뮬레이터 배포. 한국 엣지 노드(icn1), 브랜치별 미리보기 |
| Netlify | 정적 호스팅 + 서버리스 함수 | 이 규모에서 Vercel과 기능 차이 없음. 이미 쓰고 있다면 그대로 |
| Supabase | Postgres · Realtime · Auth · Storage | 결과 보드의 저장·구독. 호스팅이 대체할 수 없다 |

**채택: Vercel + Supabase.** Supabase Realtime이 Postgres 테이블 변경을 그대로 구독하는 구조라
"다른 모둠이 올리면 내 보드가 즉시 갱신"이 코드 몇 줄로 끝난다.

## 이미지를 저장하지 않는다

거름종이 캡처를 PNG로 올리면 용량과 개인정보 부담이 동시에 생긴다.
그런데 렌더러는 결정론적이다 — **같은 시드와 파라미터면 어느 기기에서든 같은 그림**이 나온다.

그래서 이미지 대신 `fieldParams()` 값만 저장하고, 보는 쪽에서 다시 그린다.
40바이트 남짓. 저장 용량도, 업로드 지연도, 이미지에 딸려 올 위험도 없다.

`supabase/schema.sql` 참조. **`submissions` 에 이미지 컬럼을 추가하지 말 것.**

## 개인정보는 처음부터 받지 않는다

- 로그인 없음. 교사가 발급한 **6자리 수업 코드 + 모둠 번호**만. 이름·학번·이메일 입력칸을 만들지 않는다
- RLS: 현재 세션의 수업 코드와 `class_id` 가 일치할 때만 조회·삽입. 다른 반 데이터는 쿼리해도 안 나온다
- `expires_at` 기본 30일. 지나면 자동 삭제
- 서술형 메모는 자유 입력이라 학생이 이름을 적을 수 있다. 제출 전 안내 문구를 띄우고,
  교사 화면에서 개별 삭제가 가능해야 한다

## 빈 보드 문제

첫 모둠이 올리기 전까지 보드가 비어 있다. 조건이 서로 다른 **시드 카드 두 장**을 미리 깔아 둔다.

- 시드 카드 1: 기포 3개가 있는 (나) 400배 결과
- 시드 카드 2: 100배로만 관찰한 (나) 결과

학생 결과가 세 장을 넘으면 시드 카드는 사라진다. 시드 카드임을 숨기지 않는다 — 「예시」로 표시한다.

## 수업 전 확인

- 학교망에서 `*.supabase.co` 와 `*.vercel.app` 이 열리는지. 막히면 커스텀 도메인으로 우회한다.
  **배포 전에 반드시 확인할 것**
- 학생 기기가 태블릿이면 드래그가 손가락으로 되는지. 포인터 이벤트로 통일하면 문제없다
- 비용: Vercel Hobby + Supabase Free 로 충분하다. 한 반 30명 × 3제출 = 수업당 90행

## 환경 변수

```
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

anon key는 공개돼도 되는 값이지만, **RLS가 켜져 있는지 반드시 확인한다.**
RLS 없이 anon key를 배포하면 테이블 전체가 열린다.
