# 05 · 결과 렌더러 — 거름종이 위의 색 띠

`src/render/strip.js` 가 구현이고 이 문서는 설명이다. 값이 어긋나면 코드가 맞다.

## 원칙

그림은 미리 그려 두지 않고 **상태에서 매번 생성**한다. 그래야:

- 찍은 횟수·전개 시간·전개액 깊이를 바꾼 결과가 정직하게 반영된다
- 기록이 이미지 대신 **값 한 벌**만 담을 수 있다 (`stripParams`)
- 같은 학생이 다시 열어도 같은 그림이 나온다

아트 디렉션(라인+플랫)은 **여기 적용되지 않는다.** 젖은 자국과 번진 띠는 굵은 외곽선으로
그릴 수 없다. **애셋을 만드는 사람은 이 파일을 읽지 마세요** — 따라 쓰면 애셋이 오염됩니다.
다만 색은 `palette.experiment.js` 를 공유한다.

## 전개 물리 — 임의로 바꾸지 말 것

`src/sim/develop.js` 에 있다. `tests/develop.test.js` 가 값을 고정한다.

```
거름종이        2 × 10 cm            PAPER_W_MM 20 · PAPER_H_MM 100
원점            아래에서 2.5 cm       ORIGIN_MM 25   ← Pearson CP11 "about 25 mm"
용매 전선       액면 깊이 + K·√시간   ← Washburn. 종이 끝(100 mm)에서 멈춘다
색소 띠         원점 + Rf × (전선 − 원점)
전개율(Rf)      (띠 − 원점) ÷ (전선 − 원점)
```

**오른 거리는 시간의 제곱근에 비례한다.** 네 배의 시간이 두 배의 거리다.
처음에 쑥 오르다 갈수록 느려지는 것은 연출이 아니라 사실이고, 그 사실이
「전개액이 상단 가까이 오면 꺼내라」는 절차가 왜 시간이 아니라 **높이**로 적혀 있는지를
설명한다 — 같은 1분이 앞에서는 3 cm 고 뒤에서는 5 mm 다.

### 화면에 시계를 띄우지 않는다

실제로는 **약 10분** 걸린다 (Pearson CP11 · CUNY Baruch Chem 1004). 그래도 시계를
띄우지 않는 이유는, **출처의 절차 자체가 시간이 아니라 높이로 적혀 있기 때문**이다 —
`When it is close to the top of the tube after around 10 minutes, remove it`. `FULL_RUN_T` 는 화면에서 전선이 오르는 **속도 감각**만
정하는 값이고, 물리인 것은 **√ 하나**다.

## 전개율(Rf) — 출처가 있다

```js
carotene     0.95      // Pearson Edexcel Biology B, Core Practical 11, table A
xanthophyll  0.71      // 용매계가 우리와 같다 — propanone : petroleum spirit = 1 : 9
chlorophyllA 0.65
chlorophyllB 0.45
```

**실리카겔 값을 넣지 마라.** 검색 상위의 표(카로틴 0.98 · 엽록소 a 0.59 · 잔토필 0.28)는
실리카겔이고, **잔토필이 맨 아래**로 내려가 있는 것으로 알아본다.

### 그래도 화면에는 말하지 않는다

여기 있는 것은 **띠를 그릴 자리**다. 학생에게 알려 줄 답이 아니다.

- 자는 **눈금만** 그린다. 읽는 것도 나누는 것도 학생이다
- 띠 이름표는 **기본이 꺼짐**이다 — 켜 두면 화면이 채점할 답을 먼저 말한다
- `tests/develop.test.js` 가 `UI` 문자열을 훑어 색소 이름·「Rf」·「전개율」 옆에
  소수가 붙으면 실패시킨다

정리 단계에서 **대조표**로 보여 주는 것은 다른 이야기다 — 출처의 원래 교수법이
「재고 → 표와 대조해 색소를 알아낸다」이기 때문이다. 아직 하지 않았고, 하려면
위 검사를 **끄지 말고 어디까지 허용할지를 다시 적어야** 한다.

### 띠가 퍼지는 정도는 그림용 값이다

`BAND_SPREAD` 는 출처가 없다. 가장 빡빡한 자리는 **잔토필(0.71)과 엽록소 a(0.65)** 이고,
실측 Rf 로 바꿨을 때 이 둘이 5 mm 안쪽으로 붙는다. 절차를 지키면 갈라지고 원점을 크게
찍으면 뭉치도록 잡았다 — `tests/develop.test.js` 가 양쪽을 다 본다.

**상대 함량은 넣지 않았다.** 네 색소의 함량 비를 확인하지 못해서, 띠 넷을 같은 진하기로
그린다. 지어낸 비율로 어떤 띠를 굵게 그리면 그 그림이 다음 사람에게 사실로 읽힌다.

## 상태 → 그림

| 상태 | 그림 |
|---|---|
| `load` 낮음 | 띠 넷이 다 옅다 |
| `submerged` | **띠가 없다.** 원점 자리도 비었다 |
| `spotMm` 큼 | 띠가 굵어 이웃과 겹친다 (`bandWidthMm`) |
| 전선이 원점 가까이 | 띠가 뭉쳐 갈라지지 않았다 |
| `overrun` | 전선을 그리지 않는다 — 어디였는지 알 수 없다 |
| `chlorophyllKept` 낮음 | **청록·황록 두 띠만** 옅어진다. 주황·노랑은 그대로 |
| `marker === 'pen'` | 잉크의 가짜 띠 둘이 섞인다 (`INK_BANDS`) |
| `grit` 있음 | 원점에 부스러기 얼룩 |
| `wetness` 있음 | 전선 아래가 젖어 색이 짙다 |
| `markedFront` | 연필로 그은 전선 자국이 남는다 |
| `rulerPlaced` | 왼쪽에 mm 눈금이 붙는다 |
| `torn` | 찢어진 종이. 띠도 눈금도 없다 |

## `idPrefix` 를 반드시 넘길 것

이 SVG 는 `<clipPath>` 와 `<linearGradient>` 를 id 로 참조한다. 같은 문서에 같은 id 가
둘 이상 있으면 브라우저는 **먼저 나온 것 하나만** 쓴다. 결과 카드를 여러 장 늘어놓으면
모든 카드가 첫 카드의 띠 색을 쓰게 되어 **에러 없이 조용히 틀린다.**

```js
renderStrip(a, { idPrefix: 'card1-' })
renderStrip(b, { idPrefix: 'card2-' })
```

`tests/strip.test.js` 가 두 장의 id 가 겹치지 않는지 검사한다.

## 애셋 안의 id 와도 부딪힌다

애셋은 인라인 SVG 라 그 안의 `<rect id="sheet">`·`<path id="origin">` 이
**문서 전체의 id 공간에 그대로 올라온다.** 화면 쪽 id 를 그와 같게 지으면
`querySelector` 가 애셋 쪽을 집고, `<label for="…">` 는 애셋의 도형을 가리킨다.
둘 다 **콘솔 에러 없이** 틀린다. `tests/dom-ids.test.js` 가 지킨다.
