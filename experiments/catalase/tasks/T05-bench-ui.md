# T05 — 실험대 조작 UI + 어포던스

**상태: 끝남.** 무엇을 왜 그렇게 했는지는 `PROGRESS.md` 의 같은 번호 절에 있다.

**어포던스까지 한 카드로 한다.** 기능만 넣고 끝내지 않는다 —
바나나랩에서 집기·채우기·문지르기가 **전부 구현된 뒤에** "이거 어떻게 하는 거야?" 를 들었다.
**기능이 있는데 어포던스가 없으면 학생에게는 없는 것과 같다.**

## 세 곳만 고친다

`src/ui/bench.js` 의 나머지(드래그·스냅·이름표·히트박스·편집 모드)는 그대로 쓴다.

```js
defaultItems()   // 실험대에 무엇이 어디에 놓이는가
dropTable()      // 무엇을 무엇에 끌어다 놓으면 무슨 일이 일어나는가
tapTable()       // 무엇을 클릭하면 무슨 일이 일어나는가
```

**조작표는 이 두 표에만 적는다.** 실제 실행 · 드래그 중 하이라이트 · 안내 문구 유무가
전부 이 표를 읽는다. 세 곳에 따로 적으면 조작을 하나 늘릴 때마다 세 곳이 어긋난다.

**표는 종류 쌍으로만 적고 상태는 보지 않는다.** 빈 핀셋을 비커에 대면 규칙 엔진이
「핀셋이 비어 있습니다」라고 답해 주는데, **그 답을 듣는 것이 배우는 내용이다.**
미리 걸러 내면 들을 기회가 사라진다.

## 배치

손으로 숫자를 적지 않는다. **배치 편집 모드**를 쓴다.

```
npm run dev  →  http://localhost:5173/experiments/catalase/?edit=1
```

「코드 복사」를 누르면 `defaultItems()` 에 붙여 넣을 코드가 나온다.

## 반드시 넣을 것

- 물건에 마우스를 올리면 **이름 + 지금 할 수 있는 조작**
- 끄는 동안 **놓을 수 있는 곳** 강조, 지금 놓을 대상은 더 강하게
- 시간이 걸리는 조작(감자즙 끓이기·원반 담그기)은 **진행 표시**
- 끄는 물건은 살짝 비치게 — 큰 물건이 아래 강조를 가린다
- 잡는 영역 최소 44 px. **판정도 같은 크기로**

## 물린 함정 (바나나랩에서 실제로)

1. **잡는 영역이 그림보다 크다.** 프레임(400×300)이 아니라 `CONTENT_BOX` 로 판정한다
2. **다시 그릴 때마다 DOM 참조가 죽는다.** 떨어져 나간 노드는 크기가 0 이다. 그때그때 조회한다
3. **빠른 드래그는 중간 이동 이벤트가 안 온다.** 누른 곳과 뗀 곳의 **거리**로 가른다
4. **포인터 이벤트만 들으면 `element.click()` 이 아무 일도 안 한다.** 보조기기가 통째로 막힌다
5. **큰 물건의 빈 여백이 옆엣것을 덮는다.** 물건끼리 겹치지 않는지 테스트로 못 박는다

## 합격 기준

- [ ] 조작표가 `dropTable()`/`tapTable()` **두 곳에만** 있고, 안내 문구와 어긋나지 않는지 테스트가 본다
- [ ] 물건끼리 겹치지 않는다 (테스트)
- [ ] `element.click()` 으로 모든 조작이 동작한다
- [ ] 하드 게이트를 새로 추가하지 않았다
- [ ] **직접 끝까지 플레이했다** — 설계 → 감자즙 → 원반 → 비커 → 수조 → 시간 재기 → 기록
