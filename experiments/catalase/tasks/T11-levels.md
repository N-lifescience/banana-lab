# T11 — 난이도 세 단계

**상태: 끝남.** 무엇을 왜 그렇게 했는지는 `PROGRESS.md` 의 같은 번호 절에 있다.

**핵심 규칙: 난이도는 설명만 줄인다. 할 수 있는 일은 세 단계가 똑같다.**
힌트를 줄여서 길이 막히면 그건 설명을 줄인 게 아니라 **강제를 넣은 것**이다.

| | 1단계 | 2단계 | 3단계 |
|---|---|---|---|
| 절차 제시 | 다음 할 일 강조 | 목록만 | 목표만 |
| 실패 안내 | 원인 + 다음 행동 | 원인만 | 원인만 |
| 말풍선 힌트 | 문장 | 짧은 구 | 이름만 |
| 예상 문항 | 선택형 | 반주관식 | 완전 주관식 |
| 되돌리기 | 무제한 | 3회 | 1회 |
| 기구 초기 설정 | 대신 맞춰 줌 | 직접 | 직접 |

## 이 실험에서 「대신 맞춰 줌」이 뜻하는 것

1단계는 **통제변인의 기본값을 채워 놓고 시작한다** (3 % 과산화수소수 · 감자즙 원액 ·
완충 용액). 조작변인은 **학생이 고른다** — 그게 이 실험의 배울 것이라 대신 골라 주면
실험 자체가 사라진다.

## 물린 함정 — 바나나랩에서 실제로

- **테스트 118개가 통과하는데 2·3단계에 닿을 방법이 아예 없었다.** 시작 화면에서 고르는
  길과 주소(`?level=2`)로 들어가는 길이 **둘 다** 있는지 직접 확인한다
- **되돌리기가 3단계에서 사실상 죽어 있었다.** 90개가 통과하는 상태였다.
  1회짜리 되돌리기가 `TICK` 을 무르는 데 쓰이면 학생에게는 없는 기능이다 —
  `TRANSIENT_ACTIONS` 에 시간 경과가 들어 있는지 확인한다
- **순서가 결과를 바꾸는 자리.** 1단계 자동 보조를 넣을 때 순서를 잘못 짜면
  앞 시행의 값이 남아 조용히 틀린다. 기본값을 채우는 순서를 테스트로 못 박는다

## 합격 기준

- [ ] **조작표가 난이도를 인자로 받지 않는다.** 1단계와 3단계의 조작표 모양이 같다 (테스트)
- [ ] 시작 화면에서 고를 수 있고, `?level=2` 로도 들어갈 수 있다. **둘 다 직접 확인했다**
- [ ] 3단계에서도 되돌리기 1회가 **실제로 쓸모 있다** (시간 경과에 먹히지 않는다)
- [ ] 3단계에서도 막힌 이유는 감추지 않는다 (`tests/toast.test.js`)
- [ ] 자기 평가는 난이도와 무관하게 같다

## 검증 명령

npm run check
npm run dev                                    # ?level=2, ?level=3 을 직접 열어 본다
