## 상태 스키마 — 이 실험의 몸통

바나나랩은 슬라이드 세 장이 나란히 있었다. 이 실험은 **시행이 줄지어 일어난다.**

```
design    조작변인(temp|ph) · 통제변인 목표값 · 종속변인(고정) · 확정 여부
bench     감자즙(농도·끓임) · 원반 · 비커(과산화수소수 %, pH 와 그 맞춘 방법, 수조 온도)
trials    기록한 시행들 — 조건 한 벌 + 시간(또는 안 뜸) + 설계와 맞는가
session   난이도·시드·모드·노트·읽은 단계·위반·정리·로그·되돌리기 (바나나랩 그대로 쓴다)
```

**`trials` 의 각 항목은 그때의 조건을 통째로 담는다.** 두 벌을 따로 만들면 어긋난다 —
그래프도, 탐구 노트도, 보고서도, 결과 보드도 전부 이 한 벌을 읽는다.

## 조작표에 반드시 들어갈 것

| 조작 | 잘못했을 때 무엇으로 답하는가 |
|---|---|
| 감자즙 만들기 · 희석 · **끓이기** | 끓인 것은 안 뜬다. 식혀도 **안 돌아온다** |
| 원반 뚫기 · 감자즙에 담그기 | 안 담근 원반은 안 뜬다 (염기 조건이면 뜬다 — 그게 배울 것이다) |
| 과산화수소수 붓기 (1·2·3 %) | 묽으면 느리다 |
| pH 맞추기 — 완충 용액 / 0.1 M 산·염기 | 완충 안 하면 pH 11 에서 **더 빨리** 뜬다 |
| 수조에 넣기 (0·20·37·60·100 ℃) | 100 ℃ 는 안 뜬다 |
| 원반 넣기 · 시간 재기 · 기록하기 | 설계와 어긋난 조건이어도 **막지 않는다.** 기록에 표시만 한다 |

### 되돌아갈 길을 같이 정한다

새 조작을 넣을 때마다 「이걸 잘못하면 어떻게 되돌아오나」를 같이 정한다.
최소한 이만큼은 있어야 한다 — **비커 비우기 · 원반 새로 뚫기 · 감자즙 새로 만들기 ·
기록 지우기.** 소모품이 바닥나지 않게 한다.

## 합격 기준

- [ ] `reduce(state, action)` 이 `{state, outcome, message, tag}` 를 돌려준다
- [ ] `outcome` 은 `ok` / `happened` / `blocked` 셋뿐이고, `blocked` 는 **허용된 두 사유에만** 붙는다
- [ ] 모든 액션을 여러 상태에서 돌려 `blocked` 가 나오면 사유가 둘 중 하나인지 보는 회귀 테스트가 있다
- [ ] `blocked` 메시지에 **어디로 가야 하는지**가 들어 있다 (「새것을 꺼내세요」로 끝나지 않는다)
- [ ] `src/sim/` 어디에도 `document`·`window`·`Date.now()`·`Math.random()` 이 없다
- [ ] `tests/kinetics.test.js` 가 T00 의 세 계열을 **순서로** 고정한다 —
      37 ℃ 가 가장 빠르다 · 100 ℃ 는 안 뜬다 · **완충하지 않은 pH 11 이 pH 7 보다 빠르다**
- [ ] 통제변인이 어긋난 시행도 **기록된다.** 막히지 않는다
