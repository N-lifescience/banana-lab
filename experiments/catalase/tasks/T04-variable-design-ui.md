# T04 — 변인 설계 UI (조작변인 · 통제변인 · 종속변인)

**상태: 끝남.** 무엇을 왜 그렇게 했는지는 `PROGRESS.md` 의 같은 번호 절에 있다.

**이 실험의 몸통이다.** 바나나랩에는 없던 화면이고, 뒤에 fermentation 이 그대로
재활용하므로 **깔끔하게 만든다.**

## 무엇을 하는 화면인가

학생이 실험을 하기 **전에** 세 가지를 정한다.

| | 무엇 | 학생이 하는 일 |
|---|---|---|
| 조작변인 | 내가 바꿀 것 | 온도 **또는** pH 를 고른다 |
| 통제변인 | 붙들어 둘 것 | 나머지 값을 정한다 — 고르지 않은 쪽, 과산화수소수 농도, 감자즙 농도, pH 를 맞추는 방법 |
| 종속변인 | 잴 것 | 원반이 떠오르는 데 걸린 시간 (**고정**. 이 실험에서 잴 것은 이것뿐이다) |

## 막지 않는다

- **설계를 안 하고 실험을 시작해도 막지 않는다.** 설계 없이 얻은 값은 나중에 그래프에서
  「무엇을 바꾼 시행인지 알 수 없음」으로 남는다
- **조작변인을 둘 다 고르는 것도 막지 않는다.** 그러면 그래프가 두 갈래로 갈려 비교가
  성립하지 않는 것이 눈에 보인다
- **통제변인을 도중에 바꾸는 것도 막지 않는다.** 그 뒤 시행에 표시가 붙는다

**표시하는 것과 잠그는 것은 다르다.** 여기서 나오는 것은 전부 표시다.

## 재활용을 염두에 둔 모양

이 UI 는 fermentation 이 그대로 쓴다. 그러므로:

- 변인의 **이름과 값 목록을 데이터로 받는다.** 코드 안에 「온도」·「pH」를 박지 않는다
- 이 실험의 변인 목록은 `src/sim/state.js` 한 곳에 있고, UI 는 그것을 읽는다
- 파일 이름은 `src/ui/design.js` — 실험 이름이 들어가지 않는다

## 합격 기준

- [ ] 조작변인을 고르면 그 변인이 통제변인 목록에서 빠진다 (같은 것을 두 번 정하지 않는다)
- [ ] 어떤 조합도 **막히지 않는다.** `disabled` 버튼이 없다
- [ ] 변인 목록이 데이터로 들어온다. `design.js` 안에 「온도」·「pH」 문자열이 없다
- [ ] 화면 문구는 전부 `strings.js` 에 있다
- [ ] **화면이 답을 먼저 말하지 않는다** — 「온도를 고르면 37 ℃ 가 가장 빠릅니다」 같은 문구 금지
- [ ] `element.click()` 으로도 동작한다 (포인터 이벤트만 듣지 않는다). 보조기기가 막히면 안 된다
