# T09 — 절차 판정표 (`src/sim/progress.js`)

**상태: 끝남.** 무엇을 왜 그렇게 했는지는 `PROGRESS.md` 의 같은 번호 절에 있다.

탐구 노트의 칸은 **실험대에 손도 대지 않고 채울 수 있다.** 그러면 노트는 관찰 기록이 아니라
받아쓰기가 되고, 실험대와 노트가 따로 논다.

여기서는 **상태만 보고** 각 세부 단계가 실제로 일어났는지 판정한다.

## 막지 않는다

**안 한 단계의 칸도 그대로 열려 있다.** 여기서 나오는 것은 **표시**이지 잠금이 아니다.
순서를 바꿔 하거나 먼저 적어 두는 것을 금지할 이유가 없다.

## 왜 `src/sim/` 에 있는가

DOM 을 모르는 순수 함수라 `node --test` 로 검증된다. 화면 안에 두면 이 판정이 맞는지
브라우저를 띄워야만 알 수 있다.

## 이 실험의 판정 대상

`UI.protocol` 의 순서와 **한 칸씩 짝**을 이룬다. 절차를 고치면 여기도 함께 고쳐야 하고,
`tests/progress.test.js` 가 개수를 맞춰 본다.

대략 이런 것들이다 — 실제 목록은 `notebook.protocol` 을 확정한 뒤에 맞춘다.

- 조작변인을 골랐는가 · 통제변인 값을 정했는가
- 감자즙을 만들었는가 · (대조군을 쓴다면) 끓인 감자즙을 만들었는가
- 원반을 뚫었는가 · 감자즙에 담갔는가
- 비커에 과산화수소수를 부었는가 · pH 를 맞췄는가 · 수조에 넣었는가
- 시행을 **몇 번** 기록했는가 (3~5회 반복이 이 실험의 절차다)

## 합격 기준

- [ ] `stepDone(state, groupId, index)` 가 순수 함수다
- [ ] `STEP_DONE` 의 칸 수와 `UI.protocol` 의 세부 단계 수가 같다 (테스트가 본다)
- [ ] **조작이 따로 없는 단계를 「아직」으로 표시하지 않는다.** 학생이 있지도 않은 단추를 찾는다
      (바나나랩에서 받침 유리가 그랬다 — 처음부터 선반에 나와 있어 꺼내는 조작이 없었다)
- [ ] `src/sim/progress.js` 에 `document`·`window` 가 없다

## 검증 명령

```bash
node --test tests/progress.test.js
npm run check
```
