# T12 — 배포본 확인

**상태: 끝남.** 무엇을 왜 그렇게 했는지는 `PROGRESS.md` 의 같은 번호 절에 있다.

**통과하는 테스트는 증거가 아니다.**

바나나랩에서 실제로 있었던 일: 테스트 140개가 통과하는데 **앱이 아예 뜨지 않았다.**
주석 안의 백틱 하나가 템플릿 리터럴을 끊었고, 규칙 테스트는 `src/sim/` 만 import 하고 있었다.

그래서 **빌드해서 띄운 뒤 브라우저로 연다.**

## 볼 것

- [ ] `npm run build` 가 통과한다
- [ ] 빌드본에서 앱이 **실제로 뜬다.** 콘솔 에러 0건
- [ ] `/harness.html` 은 개발 페이지다 — 배포본에서 링크로 닿지 않는지 확인
- [ ] 난이도 세 단계가 배포본에서도 열린다 (`?level=2`, `?level=3`)
- [ ] 처음부터 끝까지 **한 번 플레이한다** — 설계 → 감자즙 → 원반 → 비커 → 수조 →
      시간 재기 → 기록 → 조건 바꿔 3회 → 그래프 → 보고서
- [ ] 라이트/다크 양쪽에서 확인. 다크에서 버튼이 사라지지 않는지
      (바나나랩에서 `button{color:inherit}` 만 두고 배경을 안 줘서 통째로 사라진 적 있다)

## 작성자 이메일 — 여기서 반드시 본다

```bash
git config user.email       # 비어 있으면 안 된다
```

없으면 git 이 호스트명으로 가짜 주소를 지어내고, **Vercel 이 그 커밋의 배포를 통째로 막는다**
(빌드 실패가 아니라 `blocked`). **로컬에서는 아무 이상이 없다** — 검사도 초록불이고 push 도 된다.
배포된 사이트만 조용히 옛날 것으로 남는다.

## 검증 명령

```bash
npm run build
npm run preview                # 다른 터미널에서
node scripts/check-build.mjs
git config user.email
```
