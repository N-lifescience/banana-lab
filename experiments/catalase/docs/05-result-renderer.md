# 05 · 결과 렌더러 — 비커와 떠오르는 원반

`src/render/beaker.js`. 이 실험의 결과를 그리는 유일한 파일이다.

## 무엇을 그리는가

이 실험의 결과는 색이 아니라 **시간 하나**다. 그래서 이 그림이 하는 일은
**「지금 어디까지 왔는가」**를 보여 주는 것이다.

| 무엇 | 어디서 오는가 |
|---|---|
| 수조와 온도 | 조건 |
| 비커와 과산화수소수 | 조건 (`h2o2Pct` 가 0 이면 **액체를 안 그린다**) |
| **원반의 높이** | `riseProgress(conditions, elapsedS)` — 0 이면 바닥, 1 이면 액면 |
| 원반에 붙은 기포 수 | 같은 진행도. 떠오르는 순간 가장 많다 |
| **원반을 넣기 전 비커 안의 거품** | `preFizz(conditions)` |
| 원반의 색 | 감자즙을 머금었는가 · 그 감자즙이 끓인 것인가 |

## 지키는 것 셋

### 1. 순수 함수다

같은 입력이면 언제나 같은 SVG 문자열이 나온다. 난수는 `seed` 로만 들어온다.
그래야 결과를 **이미지가 아니라 값 한 벌로 저장해 두었다가** 탐구 노트와 보고서에서
되살릴 수 있다. `Math.random()` 을 쓰면 그 길이 막힌다 — 테스트가 소스를 훑어 막는다.

### 2. 물리를 여기서 계산하지 않는다

진행도와 거품 세기는 `src/sim/kinetics.js` 가 낸다. 여기서 다시 계산하면
두 곳이 어긋나는 순간 **그림과 기록이 다른 말을 하게 된다.**

### 3. `idPrefix` 를 처음부터 받는다

한 화면에 비커를 여러 개 그리는 순간(시행 비교·결과 보드) `id` 가 하드코딩이면
**에러 없이 조용히** 틀린다. 바나나랩에서 물린 자리다.

## 아트 디렉션 예외

라인 + 플랫은 **기구 애셋에만** 적용된다. 이 파일은 결과 그림이라 반투명과 잔 선을 쓴다.
색은 팔레트를 공유한다.

**애셋을 만드는 에이전트에게 이 파일을 읽히지 말 것.** 따라 쓰면 애셋이 오염된다.

## 물린 함정

### 빈 비커와 부은 비커가 같아 보였다

과산화수소수 색을 `#D9EDF2` 로 두었더니 유리색(`#E4EFEE`)과 너무 가까워,
**아무것도 안 부은 비커와 3 % 를 부은 비커가 눈으로 구별되지 않았다.**
「아직 안 부었다」와 「부었다」는 학생이 한 일이 다르므로 화면이 달라야 한다.

고친 것 셋 — 색을 유리에서 더 벌리고(`#C2E4EE`), 액체에 우하단 음영 띠를 넣고,
**액면 선**을 그었다. 액면 선이 가장 강한 단서다.

### 「안 뜬다」가 「바닥에 붙어 있다」는 뜻이 아니다

테스트에 「끓는 물에서는 원반이 바닥에 그대로 있어야 한다」고 적었다가 빨간불이 났다.
**코드가 아니라 검사가 틀렸다.** 100 ℃ 에서는 효소가 죽어도 과산화수소수 자체가 열로
서서히 분해되므로 기포가 조금씩 생기고, 원반이 조금 떠오르다 만다 — 실제로 그렇다.

「5분 안에 안 떴다」가 이 시행의 측정값이고, 그림은 왜 안 떴는지를 보여 준다.
검사는 **액면에 닿지 못한다**와 **37 ℃ 보다 훨씬 아래에 있다**로 고쳤다.
