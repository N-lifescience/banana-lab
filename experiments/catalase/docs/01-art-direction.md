## 왜 이 스타일인가

세 가지를 검토했다.

| | 준사실 | 플랫 | **라인 + 플랫** |
|---|---|---|---|
| 색 단계 | 연속 그라데이션 | 3단 | **2단** |
| 외곽선 | 0.6 px 반투명 | 없음 | **3 px 단색** |
| 블러 필터 | 3종 | 없음 | **없음** |
| 축소 내성 | 약함 | 보통 | **강함** |
| 제작 난이도 | 높음 — 잘해야 본전 | 낮음 | **낮음** |
| 다크 모드 | 배경 대비 무너짐 | 보통 | **선이 잡아 줌** |

사실주의를 80%만 달성하면 확신에 찬 평면 그림보다 싸구려로 보인다.
그리고 이 프로젝트의 그림은 감상 대상이 아니라 **조작 대상**이다.
무엇을 집을 수 있는지가 0.2초 안에 읽혀야 하고, 그 일은 명암이 아니라 윤곽이 한다.
LabXchange, PhET, 교과서 삽화가 모두 이 계열인 이유다.

## 규칙

1. **색은 `PALETTE` 안에서만.** 새 색이 필요하면 `src/style/tokens.js` 에 먼저 추가하고 왜 필요한지 주석을 남긴다.
2. **물체마다 색 2단 — 기본과 음영.** 보간하지 않는다. 익은 정도처럼 연속인 값도 **단계로 양자화**한다.
3. **외곽선은 `INK` 한 가지.** 물체마다 다른 선색을 쓰면 세트가 흩어진다.
4. **선 두께는 셋뿐.** `outline 3` / `detail 2` / `hair 1.5`. 사이 값 금지.
5. **그라데이션·필터 금지.** `<linearGradient>`, `<radialGradient>`, `<filter>`, `feGaussianBlur` 전부.
6. **광원은 좌상단 45° 고정.** 음영 도형은 광원 반대쪽 — 형태의 **우측, 하단, 또는 우하단**에 온다.
   좌측이나 상단에 음영을 두지 않는다.
7. **반투명은 두 곳만.** 접지 그림자(`GROUND_SHADOW`, 0.12)와 상태에 따른 페이드(`opacity`).
8. **`stroke-linejoin`/`linecap` 은 `round`.** `PATH_ATTRS` 를 붙이면 된다.
9. **새 애셋은 400×300 을 쓴다.** 다른 viewBox 는 같은 선 두께를 다르게 렌더한다.
   `stroke-width` 는 viewBox 단위 절대값이라, 같은 4:3 칸에 넣으면 세로가 긴 viewBox 일수록
   선이 얇아진다. 바나나만 400×312 라 약 4% 얇게 나온다 — 남겨 두되 따라 하지 않는다.

## 강제 방식

사람의 눈이 아니라 기계가 강제한다.

```bash
npm run check:art            # 등록된 애셋 전부
npm run check:art -- slide   # slide.js 하나만 (index.js 등록 전이어도 된다)
```

`SAMPLE_STATES` 의 모든 상태로 렌더링해서 위 규칙을 검사한다. 하나라도 어기면 종료 코드 1.

애셋을 다 만들었으면 `src/assets/index.js` 의 `ASSETS` 에 등록한다.
등록해야 전체 검사(`npm run check`)에 포함된다.

## 본보기

`src/assets/banana.js` 가 참조 구현이다. 나머지 애셋은 이 파일의 구조를 따른다.

- `render(state)` — 순수 문자열. 정적 생성과 린터가 쓴다.
- `applyState(root, state)` — 이미 붙어 있는 SVG를 갱신. 실행 중에 쓴다.
- `NODES` — 계약 노드 목록.

유기적인 형태(바나나, 껍질 조각)는 `src/assets/geometry.js` 의 중심선 + 폭 프로파일로 만든다.
기구처럼 직선적인 형태는 패스 문자열로 직접 적는 편이 낫다. 억지로 쓰지 말 것.
