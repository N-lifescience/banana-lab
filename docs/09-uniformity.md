# 09 · 통일 규격 — 여덟 실험이 한 앱처럼 보이게

> 사장님 지시 (2026-09-03): **「실험간, 실험기기간 통일성이 중요해. 지금 보면 통일성이
> 떨어진달까. 불쾌감도 높고.」** 여덟 실험을 같은 손으로 훑어 본 뒤 정한 규칙이다.
> 새 실험을 만들거나 있는 실험을 고칠 때 **이 문서가 기준**이다. 기계로 잴 수 있는 것은
> `tests/uniformity.test.js` 가 잰다.

왜 흩어졌는가 — 실험마다 저장소를 통째로 복제해 만들었고(`MERGE-AND-DEPLOY.md` §1),
그 뒤 각자 다른 자리에서 다른 것을 고쳤다. 정본(banana)에는 탐구 과정 STEP 카드의 CSS 가
아예 없었고, 다른 일곱은 저마다 다른 카드를 그렸다. 알림 닫기 단추 크기가 셋이었고,
자기 평가 척도가 둘이었고, 「확대 뷰」와 「확대 화면」이 섞여 있었고, 어떤 실험은 물건을
누르면 상태가 바뀌었고(잎이 시든 잎으로, 병뚜껑이 닫힘) 어떤 실험은 아무 일도 없었다.

---

## 1. 껍데기는 하나다

- 화면 CSS 는 **`packages/lab-kit/style/shell.css` 한 파일**이다. 실험 `index.html` 은
  `<link rel="stylesheet" href="/packages/lab-kit/style/shell.css">` 로 읽고, 자기 `<style>`
  에는 **그 실험에만 있는 위젯**(원심분리기의 끈·박자, 크로마토그래피의 띠, 챔버 카드,
  변인 설계 판 …)만 둔다. 공용 선택자를 실험 쪽에 다시 적으면 검사가 잡는다.
- 확대 뷰의 틀은 **`packages/lab-kit/ui/zoom-shell.js`** (`createZoomShell`).
  물건 화면은 **`packages/lab-kit/ui/item-view.js`** (`renderItemView`).
- 실험 `zoom.js` 는 **무엇을 그릴지**만 갖는다.

## 2. 실험대 — 누르면 본다, 끌면 옮긴다, 단추로 한다

| 손짓 | 일어나는 일 |
|---|---|
| **누른다** (클릭 · Enter · 탭) | 그 물건의 **화면이 열린다.** 상태는 바뀌지 않는다 |
| **끌어다 놓는다** | 놓기 표(`dropTable`)대로 **조작이 일어난다** |
| 화면 안 **단추** | 그 물건으로 할 수 있는 일이 일어난다 |

- `tapTable` 안에서 `store.dispatch` 를 부르지 않는다. 눌러서 상태가 바뀌는 물건은
  **하나도 없다.** (잎을 눌렀더니 시든 잎이 되어 있는 것, 뚜껑을 눌렀더니 닫힌 것,
  거름종이를 눌렀더니 원반이 뚫린 것 — 전부 화면 안 단추로 옮긴다.)
- **모든 물건이 누르면 화면을 연다.** 쓰레기통·폐액통·개수대·휴지·병도 예외가 아니다 —
  「무엇을 받는 곳인지」를 화면이 말한다. 눌러도 아무 일 없는 물건은 고장으로 읽힌다.
- 상단 막대: `되돌리기` · `N회 남음` · (실험이 필요하면) 문맥 단추. 순서 고정.
- 말풍선 차례: **이름 → 「클릭 — 크게 보기」 → 끌어다 놓기 안내들**. 이름은 `UI.bench.items`.

## 3. 확대 뷰 — 한 가지 모양

덮개 `#zoom` → `.zoom-panel` → 첫 자식 `닫기 (Esc)`(sticky) → `.zoom-body`.
Esc · 덮개 탭 · 닫기 단추가 다 닫고, 닫으면 열었던 물건으로 포커스가 돌아간다.
열 때마다 맨 위에서 시작한다.

본문 차례 (물건 화면 — `renderItemView`):

| 차례 | 무엇 | class |
|---|---|---|
| ① | **제목 = 실험대의 이름** (`UI.bench.items[...]`) | `h2` |
| ② | 어디에 있나 · 무엇이 들었나 — 한 줄 | `.zoom-slide-label` |
| ③ | 하는 일 — **준비물 표의 그 줄**을 그대로 쓴다 | `.zoom-empty` |
| ④ | 그림 | `.zoom-slide-stage` |
| ⑤ | 덧붙일 말 (금이 갔다 · 비었다 · 마개가 열려 있다) | `.zoom-hint[data-good]` |
| ⑥ | 여기에 끌어다 놓을 수 있는 것 — 놓기 표를 거꾸로 읽는다 | `.zoom-accepts` |
| ⑦ | 단추 — **갈 수 있는 곳만.** 못 가는 곳을 회색으로 죽여 두지 않는다 | `.zoom-action` |

- **통·상자** (받침 유리 통 · 덮개 유리 통 · 비커 통 · 모세관 통 · 거름종이 통 · 콩 통 …):
  ④ 는 **열린 통 안**이고 ⑦ 은 「꺼내기」 하나다. 종류를 골라 꺼내는 통(헤파린/민무늬)은
  종류별 「… 꺼내기」 단추가 나란히 나온다. 넣는 것은 끌어다 놓는 손짓이 한다.
- **도구·그릇** (핀셋 · 스포이트 · 비커 · 발효관 · 바이알 · 잎 …): ⑦ 은 지금 상태에서 할 수 있는
  일 — 「마개 닫기」 「뚜껑 열기」 「비우기」 「새것으로 바꾸기」 「껍질 벗기기」 …
- **받는 곳** (쓰레기통 · 폐액통 · 개수대 · 휴지): ⑥ 이 몸통이다. 안전 수칙에 걸리는 일
  (폐액 처리 · 손 씻기)은 ⑦ 의 단추다.
- **선택**(대물렌즈 4·10·40, 바깥쪽/안쪽 면, 바깥쪽/축 쪽 끝)은 `.ctrl-group` 안의
  `button[aria-pressed]` 로 한다. **연속값**(깊이 · 세기 · 각도)은 `.zoom-slider` 나 다이얼이다.
- 결과를 남기는 단추는 어디서나 **「결과 기록」** 이다 (`UI.zoom.capture`).
  micrometer 의 눈금값·세포 크기 기록은 그 앞에 따로 있고, 시야를 남기는 단추는 똑같이 「결과 기록」.

### 3.1 현미경 (banana · osmosis · micrometer)

세 실험의 현미경 화면은 **같은 차례**다. micrometer 가 먼저 잡았고(2026-09-03) 둘이 따른다.

1. 제목 「현미경」 · 재물대 상태 한 줄 (무엇이 올라가 있나 / 비었다)
2. 현미경 그림 + 시야 원 나란히 — **비었어도 그림과 빈 시야를 그린다.** 문장만 남기지 않는다.
   그림 아래에 「재물대에서 내리기」 (올라가 있을 때만)
3. 배율 줄 (접안 × 대물 = 총배율)
4. 관찰 가능성 게이지 — **100 아래면 언제나 무엇을 하면 되는지 말한다** (`hint(worst, fix)`)
5. 대물렌즈 고르기 (`.ctrl-group`)
6. 조동·미동 다이얼 + 상태 한 줄 (「호 = 0에서 돌린 정도. 초점이 맞으면 색이 든다」)
7. 조리개
8. 「결과 기록」

- 초점 허용 범위는 한 함수(`focusTolerance`)에서만 나온다. 게이지·문장·노트 ✓ 가 같은 값을 읽는다.
- 저배율에서 합격한 어떤 자리에서도 **미동나사만으로** 고배율 초점에 닿아야 한다
  (`tests/optics.test.js` 의 「미동만으로 닿는다」).
- 금이 가면 **왜 그런지 화면과 알림이 말하고**, 새것은 통·상자에서 꺼낸다. 버리는 곳은 쓰레기통.
  (micrometer 는 금 간 것이 재물대에 남았다가 「재물대에서 내리기」로 내려온다 — 사장님 지시.
   받침 유리 실험 둘은 금이 가는 순간 재물대에서 내려온다. 어느 쪽이든 알림이 다음 할 일을 말한다.)

## 4. 탐구 노트

- 머리: 「탐구 노트」 · 오른쪽에 보고서 자리. 못 만들면 `▸ 아직 남은 것이 있습니다 (N)`.
- 탭 일곱: `1. 문제 인식 … 7. 자기 평가`. 읽은 쪽은 ✓.
- 1~4 쪽 맨 밑: `.read-mark` 안에 안내 한 줄 + **「이 쪽을 읽었습니다」**(`.read-confirm`, 남색).
  3쪽은 예상을 세우기 전에는 못 넘어가고, 왜 못 넘어가는지 말한다 (`aria-disabled`, `disabled` 아님).
- 2쪽 준비물: `.materials-table` — 생김새 · 이름 · 하는 일. 카드 상자 없이 표만.
- 4쪽 탐구 과정 — **STEP 카드** (`.note-step` > `.step-summary` + `.step-body`):
  - 머리말 한 상자(`.step-lead`): 「실험대에서 한 STEP 을 마치면 ✓ 가 붙고 다음 STEP 이 열립니다.
    접힌 STEP 도 눌러서 열 수 있습니다 — 하고 나서 무엇을 보았는지 적으세요.」
  - 셈 한 줄(`.step-tally`): `STEP N개 중 M개를 마쳤습니다.`
  - **한 칸씩 연다.** 지금 STEP 의 관찰 기록을 적으면 다음 하나가 열린다. 한 번 연 것은 다시 잠기지 않는다.
  - 잠긴 STEP: 카드 안에 🔒 제목 + 오른쪽 「앞 STEP 을 먼저 적으세요」 + 밑에 「STEP n 의 관찰 기록을
    적어야 여기가 열립니다.」 — 카드 밖으로 빼지 않는다.
  - 지금 STEP: 남색 테두리 + 「지금 할 차례」 배지. 마친 STEP: 초록 테두리 + ✓.
  - 세부 단계(`.substep`): 제목 + 오른쪽 상태 알약(`아직` / `했습니다`) + **「어떻게 하는가」 한 줄**
    (`.substep-how`) + 관찰 기록 칸.
    - 제목(`label`)은 **무엇을 하는가**만 말한다 — 「비늘잎에 5×5 mm 칼집 내기」.
      그것만 읽고 실험대를 보면 무엇을 어디에 끌어다 대라는 건지 알 수 없다.
      (사장님 지시, 2026-09-04: 「STEP 을 읽어 보면, 뭘 어떻게 하라는지 설명이 너무 짧아서 못 알아먹겠어.」)
    - `how` 는 **실험대 물건 이름을 굵게** 써서 손이 할 일을 적는다 — 노트에서 읽은 이름을
      실험대 이름표에서 그대로 찾을 수 있어야 한다. `**굵게**` 는 `emph()` 가 `<b>` 로 바꾼다.
    - **없는 조작은 절대 약속하지 않는다.** `dropTable` 과 물건 화면 단추에 실제로 있는 것만 적는다.
    - `tests/uniformity.test.js` 가 셋을 본다 — 빈 `how` · 실험대에 없는 이름 · 제목을 그대로 벤 것.
- 7쪽 자기 평가: `.likert-row` 다섯 칸 — **숫자와 말이 함께** (전혀 아니다 … 매우 그렇다).

## 5. 말 — 한 가지 이름

| 쓴다 | 안 쓴다 |
|---|---|
| 확대 뷰 | 확대 화면 |
| 받침 유리 · 덮개 유리 | 슬라이드 · 커버글라스 |
| 쓰레기통 | 폐기물 통 · 휴지통 |
| 폐액통 · 개수대 · 휴지 | — |
| 결과 기록 | 결과 기록하기 · 시행 기록하기 · 사진찍기 · 두 챔버 결과 기록 |
| 관찰 가능성 | 결과의 읽을 만함 · 결과의 볼 만함 |
| STEP (탐구 과정의 큰 칸) | 단계 (난이도에만 쓴다) |
| 재물대에 올리기 · 재물대에서 내리기 | 올리기 · 빼기 |
| 되돌리기 · N회 남음 · 무제한 | — |
| 이 쪽을 읽었습니다 · 읽었습니다 ✓ | — |
| 닫기 (Esc) | 닫기 · × |
| 꺼내기 · 통에 넣기 · 쓰레기통에 버리기 | 새것 꺼내기 · 도로 넣기 |

- 배치 편집 문구(`UI.edit`)는 여덟이 글자까지 같다 — 정본은 banana.
- 보고서 창의 칸(`UI.report.fields`)과 자리 표시 글도 여덟이 같다.
- 확대 뷰 제목은 물건의 실험대 이름이다. 「(가) 슬라이드 제작」이 아니라 「받침 유리 (가)」.
