# 08 · 구현 순서와 완성 판정

## 순서

한 번에 전부 만들지 않는다. 각 단계는 그 자체로 실행되고 눈으로 확인되는 상태에서 끝난다.

| 카드 | 내용 | 끝났다는 것 |
|---|---|---|
| T01 | 상태 머신 | UI 없이 정상 경로와 모든 실패 경로가 테스트로 통과 |
| T02 | 애셋 12종 | `npm run check:art` 통과, 하네스에서 전부 보임 |
| T03 | 시야 렌더러 | 배율·초점·염색을 슬라이더로 흔들어 검증 |
| T04 | 조작 UI | 드래그·드롭, 확대 뷰 전환, 결과 메시지 연결 |
| T05 | 탐구 노트 | 7단계 패널, 기록칸, 서술형 첨삭 |
| T06 | 결과 보드 | Supabase 연동, 시드 카드, Realtime 갱신 |
| T07 | 난이도·다듬기 | 3단계 분기, 접근성, 모바일, 다크 모드 |

참조 구현이 들어 있다. 이걸 본보기로 나머지를 채운다.

## 완성 판정 체크리스트

기능이 아니라 **설계 의도가 살아 있는지**를 본다. 하나라도 아니면 아직이다.

### 강제하지 않는가

- [ ] 덮개 유리 없이 400배로 관찰이 **되기는 되는가**. 막혀 있으면 개정 취지가 사라진 것
- [ ] 한 방울만 떨어뜨렸을 때 **시야 안에 경계가 보이는가**. 전체가 옅어지기만 하면 잘못 구현한 것
- [ ] 고배율에서 조동나사를 돌렸을 때 슬라이드가 실제로 깨지고, 다시 만들어야 하는가
- [ ] 흐린 상이 기록되고, 정리 단계에 성찰 문항이 붙는가
- [ ] `tests/rules.test.js` 의 「하드 게이트는 두 종류뿐이다」가 통과하는가

### 과학적으로 맞는가

- [ ] (가)에서 아무 색도 나타나지 않는가. 대조군이 대조군답게 지루한가
- [ ] (다)에서 지질 방울이 **드물게** 보이는가. 녹말립처럼 가득 차 있으면 틀린 것
- [ ] 40배에서 녹말립이 개별로 보이지 않는가. 보이면 광학 스케일이 틀린 것
- [ ] 두껍게 바른 시료가 실제로 **보이지 않는가**. 경고만 띄우고 잘 보이면 의미가 없다
- [ ] 스포이트를 안 씻으면 한 시야에 두 색이 섞여 나오는가

### 만듦새

- [ ] `npm run check:art` 통과. 그라데이션·팔레트 밖 색·임의 선 두께 0건
- [ ] 같은 시드로 두 번 그리면 같은 그림, 다른 시드면 다른 그림인가
- [ ] 다크 모드에서 청람색과 선홍색이 모두 식별되는가
- [ ] 결과 보드에 이미지가 저장되고 있지는 않은가. 시드와 파라미터만 오가야 한다
- [ ] 학생 이름·학번을 입력받는 칸이 어디에도 없는가

### 교육적으로 작동하는가

- [ ] 서술형에 "녹말은 청람색"만 쓰면 통과하지 못하는가. 분포를 물었으므로 분포를 써야 한다
- [ ] 실패한 학생이 **무엇을 고쳐야 할지** 화면에서 알 수 있는가 (`observability().worst`)
- [ ] 다른 모둠 결과가 왜 다르게 보이는지 조작 조건으로 설명할 수 있는가
