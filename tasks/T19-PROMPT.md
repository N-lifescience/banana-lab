# T19 애셋 — 실험실 배경 (실험대)

실험대가 실험대 같지 않습니다. 지금은 **허공에 떠 있는 선반 하나와 타일 슬래브 한 장**입니다.
방이 없어서 몰입이 안 됩니다 (LabXchange 와 견주어 본 사람 피드백).

고칠 파일은 **`src/assets/bench.js` 하나**입니다. 도구 애셋 13종은 그대로 둡니다.

참고 사진: 사람이 따로 전달합니다 — 현대적인 학교 실험실. 검은 상판, 흰 프레임,
상판 가운데 선반 구조물, 흰 바닥과 격자 천장의 매입 조명.

---

## 붙여 넣을 프롬프트

banana-lab 저장소의 `src/assets/bench.js` **한 파일만** 다시 그린다.
다른 애셋 13종과 `src/ui/`, `src/assets/contract.js` 는 건드리지 마라.

먼저 `npm run dev` 로 서버를 띄우고 **`http://localhost:5173/`** 을 연다.
애셋 시트가 아니라 **실제 실험대 화면**을 보면서 그린다. 이 그림은 혼자 보는 그림이 아니라
바나나·현미경·시약병이 그 위에 올라앉는 **바닥**이다.

### 지금 무엇이 문제인가

1. **방이 없다.** 벽도 바닥도 천장도 없이 선반과 상판만 떠 있다. 배경이 CSS 단색이라
   물건들이 색종이처럼 붙어 있는 것처럼 보인다.
2. **상판이 타일 격자다.** 가로 2줄 세로 2줄을 그어 놓아서 실험대 상판이 아니라
   화장실 타일로 읽힌다.
3. **깊이가 없다.** 상판이 앞으로 뻗어 있는데 두께도 앞 모서리도 안 보인다.

### 무엇을 그리는가

**한 사람이 쓰는 실험대 자리 하나.** 뒤에 벽, 위에 천장과 조명, 벽에 붙은 선반,
그 앞으로 뻗어 나온 상판. 상판 앞쪽(화면 아래 절반)은 학생이 물건을 늘어놓는 자리다.

`#room` 이라는 그룹을 **새로 만들어** 거기에 방을 그린다 (계약에 이미 선언돼 있다, 선택 노드).

- **천장** — 격자 무늬 텍스처 천장. 매입 조명 두세 개. 그리는 것은 조명 **기구**다,
  빛 번짐이 아니다 (블러·그라데이션 금지).
- **뒷벽** — 선반이 붙어 있는 벽. 밋밋하면 콘센트나 가스 밸브를 하나 정도.
- **바닥** — 상판 옆으로 조금 보이는 정도면 된다. 없어도 된다.
- **깊이** — 소실점 하나짜리 얕은 원근. 다른 애셋과 같은 3/4 시점을 깨지 않는 선에서.

`#surface` 는 **에폭시 상판**으로 다시 그린다.

- 타일 격자를 지운다. 이음매가 필요하면 **세로선 한두 개**로 족하다.
- 앞 모서리에 **두께**를 준다. 상판이 판때기가 아니라 덩어리로 보여야 한다.
- 상판은 어둡게 — 참고 사진의 검은 에폭시다.

`#shelf` 는 참고 사진처럼 **기둥이 받치는 선반**으로. 지금은 벽에 브래킷 두 개로 붙어 있다.

### 반드시 지킬 것 — 이걸 어기면 실험대 위 물건이 전부 허공에 뜬다

**두 선의 y 좌표는 절대 옮기지 마라.**

| 그룹 | 그 그룹에서 **가장 위쪽 y** | 무엇인가 |
|---|---|---|
| `#shelf` | **65** | 선반 상판의 윗면. 여기에 바나나·받침 유리·시약병이 선다 |
| `#surface` | **155** | 작업면의 앞 모서리. 여기에 개수대·현미경·쓰레기통이 선다 |

`src/ui/bench.js` 가 이 두 숫자로 물건의 높이를 정한다. 그림만 보면 멀쩡한데
물건이 1 cm 씩 떠 있게 되고, 아무도 눈치채지 못한다.
**벽·천장·바닥처럼 이 선보다 위에 있는 것은 전부 `#room` 에 넣어라.**
`#shelf` 나 `#surface` 안에 넣으면 그 그룹의 최상단이 올라가면서 검사가 실패한다.

```bash
node --test tests/assets.contract.test.js   # 「실험대 배경의 랜드마크가 제자리에 있다」
```

### 그 밖에 지킬 것

- `viewBox` 는 `0 0 400 300` 고정. **프레임을 꽉 채운다** — 이 그림만은 여백을 두지 않는다.
  방이니까 화면 끝까지 가야 한다
- `NODES` 배열: `#surface`, `#surface-shade`, `#shelf` 는 **그대로 두고**, `#room` 을 더한다
- `export` 셋: `NODES`, `render(state)`, `applyState(root, state)`. 상태는 없다
- 색은 `src/style/tokens.js` 의 `PALETTE` 값만. 선 색은 `INK` 하나.
  두께는 `STROKE.outline(3) / .detail(2) / .hair(1.5)` 셋뿐
- 그라데이션·필터·블러 금지. 광원은 좌상단 45° 고정
- **파란색을 쓰지 마라.** 참고 사진의 파란 배관이 예뻐 보이겠지만, 팔레트의 파랑
  (`stainStarch`)은 **녹말 반응색(청람색)**이다. 실험대에 그 색이 있으면 학생이
  현미경으로 본 결과와 헷갈린다. 배관이 필요하면 `metal` 을 써라
- 색 배치 참고: 상판 `bodyDark`, 프레임·캐비닛 `paper`, 벽·천장 `bench`,
  금속 부품 `metal`. 더 나은 조합이 있으면 팔레트 **안에서** 바꿔라

### 가장 흔히 놓치는 것 — 물건이 묻힌다

상판을 어둡게 하면 **현미경과 쓰레기통이 사라진다.** 둘 다 `bodyDark` 로 그려져 있어서,
같은 색 상판 위에 놓이면 실루엣이 없어진다.

상판을 `bodyDark` 로 칠할 거면 그 위에 서는 물건과 **명도 차이가 나는 쪽**을 골라라
(예: 상판은 `bodyDark[1]`, 물건은 `bodyDark[0]`). 어느 쪽이든
**실제 화면에서 현미경이 상판에서 떨어져 보이는지 눈으로 확인해라.**

### 끝났는지 확인하는 법

```bash
npm run check                              # 테스트 + 아트 디렉션 린터
node --test tests/assets.contract.test.js  # 랜드마크
```

둘 다 통과해야 한다. 그다음 **반드시 눈으로** 확인한다.

```bash
npm run dev
```

`http://localhost:5173/` — 애셋 시트가 아니라 실제 화면이다.

- 물건이 선반과 작업면에 **닿아** 있는가 (떠 있거나 파묻히지 않았는가)
- 현미경·쓰레기통·개수대가 상판에서 떨어져 보이는가
- 방으로 보이는가 — 벽·천장·바닥이 서로 맞물려 있는가
- 열네 종 도구와 같은 선 두께·같은 시점인가
- 라이트 모드와 다크 모드 양쪽에서 봤는가

## 사람이 알아 둘 것 (프롬프트에 포함하지 않음)

- 랜드마크가 이 작업의 유일한 위험이다. 그림을 아무리 잘 그려도 y=65 / y=155 가 밀리면
  실험대 위 물건이 전부 뜬다. 그래서 `tests/assets.contract.test.js` 에 검사를 먼저 넣었고,
  일부러 5 px 옮겨서 실제로 실패하는 것까지 확인했다.
- `index.html` 의 `.bench-stage{background:#DDE3DA}` 가 지금 벽 노릇을 하고 있다.
  `#room` 이 프레임을 꽉 채우면 그 CSS 는 보이지 않게 되고, 나중에 지워도 된다.
- 파란색 금지는 취향이 아니라 규칙이다 (`docs/01-art-direction.md` — 팔레트의 염색 반응색은
  시야 렌더러와 공유한다). 실험대에 청람색이 있으면 결과를 읽는 눈이 흐려진다.
