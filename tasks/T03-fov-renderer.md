# T03 · 시야 렌더러 확장

## 목표

`src/render/fov.js` 가 이미 동작한다. 빠진 상태 반영을 채우고 성능을 확인한다.

## 먼저 읽을 것

- `docs/05-fov-renderer.md` — **광학 수치 전부**
- `src/sim/optics.js`
- `tests/optics.test.js`

## 건드릴 파일

```
src/render/fov.js
src/sim/optics.js       (수치는 바꾸지 말고, 필요한 헬퍼만 추가)
tests/optics.test.js
tests/fov.test.js       (새로)
```

## 할 일

1. 시야 이동 — 드래그로 시야를 옮길 수 있게 하고, **실제와 같이 반대 방향으로** 움직이게 한다
2. 반응 진행 중 상태 — `reactionT < 1` 이면 염색이 아직 옅게, 시간이 지나며 짙어지게
3. 파손된 슬라이드 — 금이 간 선을 시야에 그린다
4. `tests/fov.test.js` 추가: 같은 파라미터면 같은 SVG 문자열, 파라미터 하나만 바꾸면 달라짐
5. 성능: 40배(세포 900개 이상)에서 렌더 시간을 재고 16 ms 를 넘으면 셀 격자를 `<pattern>` 으로 대체

## 하지 말 것

- **광학 상수를 바꾸지 말 것.** 시야 지름 18000/배율, 세포 150 µm, 녹말립 30 µm, 지질 방울 14 µm
- **지질 방울 개수를 늘리지 말 것.** 바나나 지방 0.3 % 라 드문 게 맞다
- 40배에서 녹말립을 개별로 그리지 말 것. 실제로 분해되지 않는다
- 염색 강도를 연속 보간하지 말 것. 없음 / 옅음 / 완전 세 단계

## 합격 기준

- [ ] **다섯** 조합이 눈에 띄게 구별된다: (가) 대조군 · (나)×1방울 · (나)×2방울 · (다)×1방울 · (다)×2방울

  처음에 "여섯 조합 = (가)/(나)/(다) × 1방울/2방울" 이라고 적었지만 여섯 번째는 없다.
  `DROP` 은 스포이트가 비어 있으면 방울을 세지 않고, 아니면 `stain` 을 반드시 채운다.
  그래서 `drops > 0` 이면 시약은 절대 null 이 아니고, **(가) 대조군은 방울 0개인 한 상태뿐**이다.
  「방울이 있는 슬라이드는 반드시 시약이 정해져 있다」 테스트가 이 불변식을 지킨다.

- [ ] 1방울에서 **시야 안에 경계가 보인다**
- [ ] 2방울이면 시야를 어디로 옮겨도 고르게 염색돼 있다
- [ ] 5방울에서 상이 둘로 겹친다
- [ ] 40배·100배·400배가 세포 개수로 구별된다
- [ ] 교차 오염에서 두 색이 함께 나온다
- [ ] `npm run test` 통과 (optics + fov)
- [ ] 총 400배 렌더가 16 ms 이내

  성능 기준을 처음에는 "40배(세포 900개 이상)" 라고 적었지만 그쪽이 무거운 게 아니다.
  비용을 지배하는 것은 세포 수가 아니라 **녹말립 수**라서, 가장 무거운 것은 총 100배다
  (셀 290개에 녹말립 5780개). `node scripts/perf-fov.mjs --dom` 으로 잰다.
  총 100배는 브라우저까지 합쳐 60 ms 대라 이 기준을 넘는데, 초점·조리개·시야 이동은
  속성만 바꾸면 되므로 드래그 경로에 없다. `src/render/fov.js` 머리말 참조.
